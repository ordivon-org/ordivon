## Semantic decomposition: do not collapse five different truths

1. **Run/work continuity:** precise task/run status, event history, revision and cursor. Natural Owner: Host or Harness. These are not learned facts.
2. **Physical effect:** Job/Attempt and artifact evidence. Natural Owner: Runtime, Git or the external producer. It cannot be produced by summarizing a Work note.
3. **Domain fact/claim:** statement + source + scope + observed time + validity + contradiction/withdrawal. Natural Owner: the research/business source; derived knowledge is an optional projection.
4. **Procedure/Skill:** reproducible instruction to perform a task, with explicit pre/postconditions and negative controls. Natural Owner: installed Skills plus domain acceptance.
5. **Retrieval/context view:** indexes and assembled model input for one task. Derived and replaceable; Harness may consume but it does not become the source of truth.

An Agent claim that "a migration completed" is **not** a Runtime/PG completion receipt. A prior statement that "GBrain supports corrections" is project documentation, not proof of end-to-end Ordivon applicability.

## P0 experimental qualification against real consumer

### P0-A: bounded Agent re-entry
- Baseline: current Host Work -> Topic -> Message -> Attention plus Harness Run and Runtime truth when needed.
- Candidate: one pinned ai-memory handoff operator, **not** its whole SQLite/markdown authority.
- Positive: independently authenticated second Agent resumes the same task, names correct current action and avoids duplicate physical effects.
- Negative: prior Work text says "complete" but actual Runtime Job still starting/UNKNOWN; candidate must not assert success.
- Currently **UNKNOWN / not claimed as production acceptance**: this Catalog study did not execute an independently authenticated dual-principal consumer handoff. Code/source-level review cannot substitute for that separate Owner acceptance.

### P0-B: evidence correction / invalidation
- Baseline: existing Research Claim + evidence-change impact and selected consumers.
- Candidate: GBrain fact correction/withdrawal semantics **only if** source/validity propagation is missing.
- Positive: a newly authoritative correction updates exactly the affected claim/consumer within a reviewed scope.
- Negatives: source is absent, contradiction unresolved, or a dependency is unregistered -> **UNKNOWN**, never silent reuse; old Git statement must not override authoritative withdrawal.
- Currently **SOURCE-DESIGN_ONLY / no Ordivon consumer parity**; the existing Research pilot already addresses a narrower scoped problem.

### P0-C: Context selection
- Baselines: zero long-term memory, raw cited source lookup, and current Host/Working View.
- Candidate: compiled wiki, hybrid retrieval and optional graph traversal in sequence, not all features at once.
- Acceptance: better completed task correctness or lower successful-task time/token cost; cite original source; maintain abstention on absent facts.
- Negative: a similar-looking source from a different time/scope cannot outrank exact source identity. No benchmark results were measured this pass.

### P0-D: security and source authority
- External Markdown and summaries are **data**; retrieved Skill/README instructions cannot grant tool authority.
- Query/ingest must respect principal scope; cross-Agent memory visibility is not automatic.
- Withdrawal of actively served derived memory does not imply physical deletion of all raw evidence, Git history or private backups. Erasure semantics and preservation obligations require separate Owner policy.
- Independent authentication / approved read scope remain **UNKNOWN** at this Catalog stage.
