# Provider: Reasoning Waist

Status: **REPOSITORY-NATIVE SMOKE PASS / THIN COMPOSITION PROVIDER**
Current validation environment: Python 3.14.7 selected by `.python-version`, dependencies resolved by `uv.lock`.

## Role

A small bundle of mature reasoning providers used before execution orchestration:

```text
problem/model
  -> validate semantic shape
  -> solve bounded configuration/constraints
  -> generate bounded plan
  -> hand plan/configuration to an execution or domain provider
```

It is not a universal Ordivon ontology, planner, workflow engine, decision truth source, or domain model.

## Current repository binding

The reproducible smoke is:

```bash
uv run --locked --group reasoning python scripts/check_reasoning_waist_r1.py
```

There is no second reasoning-specific requirements/lock file. `pyproject.toml` declares the group and `uv.lock` owns the exact resolution.

Current validated provider versions:

| Function | Mature provider | Version |
| --- | --- | ---: |
| combinatorial configuration / optimization | Google OR-Tools CP-SAT | 9.15.6755 |
| logical consistency / satisfiability | Z3 | 5.1.0.0 |
| planner-neutral planning API | Unified Planning | 1.3.0 |
| lightweight classical planning engine | UP Pyperplan | 1.1.0 |

| SHACL graph validation | pySHACL | 0.40.1 |

The smoke validates SHACL shape acceptance/rejection, a bounded OR-Tools configuration, an independent Z3 consistency check, and a four-action Unified Planning plan generated by Pyperplan. It prints current observations and does not rewrite historical acceptance receipts.

## Authority boundaries

- OR-Tools solves the encoded optimization/configuration problem; it does not prove that the real-world model is correct.
- Z3 proves properties of the encoded formulae only.
- Unified Planning supplies planning abstractions; the selected engine and problem model own their own semantics.
- Pyperplan is a bounded smoke engine, not a default production planner.
- RDFLib stores and queries graph statements; it does not make those statements true.
- pySHACL validates graph shape constraints; conformance is not domain correctness.

## BPMN / CMMN / DMN boundary

Process, case-management, and decision-table semantics remain outside this bundle and should use mature providers only when a real workload requires them. A Flowable 8.0.0 image was historically accepted in the 2026-09-14 evidence, but that image is not currently present on this machine and is not part of the repository-native reasoning group. Revalidate any such provider when it is reactivated; do not inherit historical deployment standing.

## Execution handoff

The reasoning bundle stops before physical execution. Its output may be handed to n8n for integration automation, Temporal for durable workflow semantics when needed, Runtime for exact physical execution/evidence, or a domain-native provider.

No execution provider inherits semantic truth from the reasoning layer.
