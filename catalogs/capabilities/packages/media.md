# Package: Media

Last census: 2026-09-13
Standing: **READY_FOR_REAL_WORK**

## Outcome scope

Turn grounded source material and communication intent into audience-facing image, audio, video, animation, editorial or mixed-media output that is technically usable, rights-aware and fit for its target audience/platform.

Media is not the universal owner of representation or truth. Source facts stay with their source authority; Artifact owns target-native artifact mechanics when invoked; Distribution owns external publication effects when invoked.

## Mature external knowledge owners

Use the subset relevant to the medium and destination:

- editorial, narrative, photography, audio, video, animation and post-production professional practice;
- SMPTE Standards / Recommended Practices / Engineering Guidelines for applicable professional media technology and interoperability;
- W3C WCAG 2.2 for applicable web/digital accessibility requirements;
- IPTC Photo Metadata for professional image descriptive/administrative/rights metadata;
- C2PA Content Credentials when cryptographic media provenance/authenticity is required;
- platform-native encoding, publishing, moderation and accessibility requirements;
- applicable copyright/licensing/rights regimes and asset licenses.

There is no need for a private Ordivon media standard that replaces these owners.

## Core representation loop

The minimal Media loop is:

`STATE -> TRANSFORM -> REPRESENT -> OBSERVE -> REVISE`

Media owns the chosen meaning/representation within its bounded workload, not upstream fact truth or downstream delivery authority. Representation is replaceable; required semantics must not be silently lost during transformation.

When Media is compiled into a deliverable Artifact, use the shared cross-surface contract:

`INTENT -> REPRESENTATION -> ARTIFACT -> CONSUMPTION -> EVIDENCE -> REVISION`

Here Media is responsible for representation, while Artifact is responsible for reliable target-native consequence. A beautiful render cannot upgrade source truth, and a valid file cannot substitute for required real consumption.

## Observed local capability

- FFmpeg / ffprobe;
- ImageMagick;
- Blender;
- Godot when real-time/interactive rendering is useful;
- ComfyUI is an on-demand candidate for reusable generative image/video/audio/3D/model workflows; it is not currently installed locally and should be activated only when a real generative-media workload justifies model/GPU/node-pack cost. Its workflow engine, caching, model memory management and custom-node ecosystem remain provider-owned rather than Media/Ordivon infrastructure;
- Artifact package/provider for family-native validation and packaging;
- Distribution provider for publication/read-back effects;
- Research package/Skills for source grounding;
- historical `/root/projects/ordivon-media` contains production/QC/timed-text/rights/editorial lessons and optional Studio equipment.

The historical Media repository is a knowledge/evidence source. Its broad `structured mediation` ownership is not automatically a forward Ordivon architecture responsibility.

## Concrete current gaps

No generic media capability gap is proven.

Add or activate a specialist editor, codec, captioning/transcription stack, DAM, camera/raw workflow, color-management system, loudness tool, platform adapter or human audience study only when a real media task requires it.

## Acceptance workload

Use the next real public-facing media request:

`goal/audience -> grounded source -> medium/editorial design -> production -> native technical QC -> rights/accessibility checks -> artifact validation -> authorized distribution/read-back if requested`

Human comprehension, preference, trust or enjoyment claims require appropriate human evidence; an Agent visual check cannot establish them by itself.
