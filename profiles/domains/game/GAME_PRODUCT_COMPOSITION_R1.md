# PC01 — Causal Works

**Standing:** `LEAD_COMPOSITION / BUILD_COMPOSITION_FALSIFIER_FIRST`

### Player promise

> I built and understand this system well enough to diagnose it when incomplete information, changing objectives, and new constraints make yesterday's solution fail.

### Player/context

Solo systems/inference player. Compact sessions of roughly 15–40 minutes. Mouse-first 2D/2.5D representation is sufficient for the first valid carrier.

### Repeated core loop

```text
observe symptoms / throughput
→ choose what to inspect under scarce diagnostic budget
→ form causal hypothesis
→ reroute / reallocate / reconfigure automation
→ commit one operating cycle
→ inspect delayed consequences
→ update system model
→ changed objective/rule revalues the existing architecture
→ repeat
```

### Session arc

```text
stable small system
→ first objective solved
→ objective/rule/constraint changes
→ old architecture becomes locally wrong, not globally useless
→ player diagnoses why
→ architecture is revised rather than discarded
→ final state records both system structure and acquired knowledge
```

### Persistent/meta structure

The primary long-horizon progression is **knowledge + architecture history**, not scalar upgrades. The player may gain new verbs only when they change the causal question; the default progression is that the same stable grammar is revalued by new operating contexts.

### Anchor mechanisms

- `bottleneck`
- `routing / network-flow`
- `machine-allocation`
- `partial-observation`
- `inspection-cost / information-scarcity`
- `feedback-control`
- `respec-reconfiguration`
- `required-goal / multi-objective-tradeoff`

### Supporting motifs

- `m01` stable grammar, changing context
- `m06` scarcity creates choice only with legible alternatives
- `m11` readable causality supports mastery
- `m22` automation can move agency upward
- `m24` knowledge can be the only permanent upgrade
- `m29` rule growth can revalue routine work
- `m30` indirect control needs delayed causality to remain legible

### Strong local evidence inherited

- D03: information scarcity can create evidence-selection value.
- D05: objective changes can move bottlenecks and force materially different allocations/architectures.
- Station Zero measured causal-leverage results: controls should earn surface area through relevant-state consequence; hidden prerequisites should be exposed before coherent rules are rewritten.
- Composition Search R1/R2 already isolates partial-observation + bottleneck, timed investigation, and path-dependent automation as bounded unresolved couplings.

### R1 failures explicitly avoided

- Not T01: the product is not a two-inspection mystery whose value collapses under one bounded policy.
- Not T02: bottleneck migration is not asked to carry the entire product thesis; it is coupled to information acquisition, diagnosis, persistence, and changing objectives.
- Not T03: no universal sealed plan is treated as the core.
- Not T04: no audience approval is required.
- Not T05: motor mastery is not the product claim.

### Product-level differentiation to test

The differentiated claim is not “factory game + hidden information.” It is:

> **diagnosis is itself a scarce strategic action, and understanding the causal system is what allows an authored architecture to survive changing objectives.**

The composition is invalid if hidden state merely withholds the obvious answer or if automation removes consequential choices.

### Market projection

Primary neighborhoods: `Automation / Factory`, `Management / Builder`, `Investigation / Mystery`, `Systemic Immersive Problem-Solving`, with possible `Puzzle` adjacency.

These are discovery labels only.

### Production shape

Low-to-medium art burden; high systems/UI/causal-legibility burden; no online requirement; no runtime LLM requirement. Godot is sufficient for a bounded composition carrier.

### Cheapest whole-composition falsifier

Build one **three-cycle diagnostic micro-factory** by composing existing MC01/MC02/CS2-02 ideas rather than creating a new mechanic:

1. 5–7 nodes, 2 resources, 2 routes, one visible output objective;
2. two optional diagnostics sharing a scarce action/time budget;
3. one hidden but inferable internal condition;
4. cycle 2 changes the desired output mix;
5. cycle 3 adds one rule/constraint that revalues the player's prior architecture;
6. architecture persists across all cycles;
7. replay/log exposes causal consequence after commitment.

### Kill conditions

Kill or radically recombine PC01 if:

- diagnostics are mandatory chores rather than strategic choices;
- hidden state only delays an obvious fix;
- optimal architecture remains effectively invariant across changed objectives;
- the player can succeed by local patching without forming a better system model;
- automation removes the remaining meaningful decision surface;
- causal consequences cannot be explained after a cycle.

# PC02 — Persistent Workshop

**Standing:** `SECONDARY_COMPOSITION / REUSE_PGP_I`

### Player promise

> I can make something for my own purpose, keep it, expose it to different contexts or audiences, and revise it without turning my work into optimization for a judge.

### Core loop

```text
state self-authored intent
→ compose under bounded materials/grammar
→ commit artifact
→ artifact enters a context / responsive audience
→ receive qualitative non-authoritative consequence
→ later affordance changes because the artifact persists
→ revise while preserving or intentionally changing intent
```

### Anchor mechanisms

`constrained-building, create-edit, save-revision, build-path-dependency, world-state-persistence, responsive-critique/audience, self-authored-goal`

### Supporting motifs

`m02, m04, m05, m10, m12, m23, m33`

### Strong local evidence inherited

D14 shows responsive-other structure can change creative strategy without proving an LLM is needed. PGP-I proves the bounded compose/save/compare apparatus mechanically. R1 T04 provides a hard negative boundary: responsiveness alone is insufficient when creator-intent retention falls below the declared requirement.

### Product-level differentiation to test

The audience/context does **not** own the objective function. Persistence must cause new affordances and constraints, while the player's declared intent remains an independent axis.

### Market projection

`Sandbox / Creative`, `Simulation`, `Puzzle`, `Experimental`, possibly `Management / Builder` depending realization.

### Production shape

Low simulation cost, potentially high expression/content cost if expanded too early. Initial carrier must remain symbolic/graphic and deterministic. Runtime model cognition is not admitted unless a cheaper responsive policy fails a claim that matters to the product.

### Cheapest whole-composition falsifier

Reuse PGP-I for three rounds. Require pre-round intent statement, persistent artifact state, two deterministic audience/context profiles, one later affordance derived from the committed artifact, and one opportunity to reject audience preference while still progressing.

### Kill conditions

- players revise mainly to satisfy the evaluator;
- persistent artifact does not change later possibility;
- one build dominates all contexts;
- authored intent becomes decorative metadata;
- the response channel behaves as a disguised scalar score.

# PC03 — Loop Cartographer

**Standing:** `ANTI_SYSTEM_BIAS_COMPOSITION / REUSE_PGP_A + KNOWLEDGE CARRIER`

### Player promise

> I master a compact place by understanding how it works; knowledge and practiced movement open routes that inventory keys cannot.

### Core loop

```text
traverse with a stable small verb set
→ fail / observe / discover a world or route rule
→ retain knowledge across reset
→ retry immediately
→ apply knowledge to a different route
→ choose safe versus demanding line
→ convert understanding + execution into a shortcut
```

### Anchor mechanisms

`jump / movement, timing-window, fast-retry, rule-discovery, shortcut-discovery, gating-by-knowledge, landmark-navigation, safe-vs-risky-route`

### Supporting motifs

`m03, m11, m20, m24, m27`

### Strong local evidence inherited

PGP-A provides a mechanically valid movement/timing carrier. D03 supports information scarcity/knowledge agency in a separate context. External motif evidence from Celeste/Trackmania/Outer Wilds supplies mature precedent for attributable retry, tiny-verb mastery, and knowledge persistence without implying causal success for this composition.

### Product-level differentiation to test

Progression is primarily **player-stored knowledge + skill**, with minimal item gating. A discovered rule must change later navigation; movement execution must remain meaningful after the route is understood.

### Market projection

`Platformer`, `Adventure / Exploration`, `Puzzle`, with possible `Experimental` adjacency.

### Production shape

Low systems complexity, medium level-design burden, higher feel/polish sensitivity than PC01/PC02. No runtime Agent requirement.

### Cheapest whole-composition falsifier

Reuse PGP-A movement carrier and add a 4–6 region looping map with one stable traversal rule, one knowledge-only shortcut, two matched safe/fast lines, and one reset that removes world progress but preserves player knowledge.

### Kill conditions

- discovery reduces to pixel hunting;
- route understanding removes execution challenge entirely;
- repeated traversal becomes dead time;
- the knowledge rule does not alter a later route decision;
- performance differences are mainly route discovery rather than learned control.
