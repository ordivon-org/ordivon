# Domains

Each domain directory is a life-cycle profile, not an independent platform.

A domain profile should progressively describe:

- Entity/Service/System of Interest;
- domain boundaries and stakeholder outcomes;
- life-cycle model;
- problem taxonomy;
- applicable external standards and bodies of knowledge;
- domain methods and algorithms;
- required enabling capabilities;
- reusable workflows/compositions;
- V&V and acceptance mappings;
- domain-specific information items.

Domain profiles are activated according to real demand. `game`, `research`, `software` or any future domain is a catalog/profile entry, not a mandatory stage in Ordivon evolution. Mature external bodies of knowledge and life-cycle practices are adopted when that domain is active.
