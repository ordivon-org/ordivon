# Episode analytical evidence to a real Harness coding task: bounded negative result

Date: 2026-11-09.

**Standing: FOUR_REAL_CODEX_TASK_RUNS_COMPLETED; NO_OBSERVED_TASK_SUCCESS_UPLIFT.**
This is not a causal population estimate or evidence that all actionable
Episode-memory systems are ineffective.

## Business question and natural Owner responsibilities

The final business need is an actually correct software repair, not a
repository statistics answer. Harness owns task execution quality, the
frozen task contract and its hidden oracle. Research owns this comparison.
Data supplies exact producer-qualified Episode information only, through
the previously implemented Research handoff. Runtime/Agent executes the
actual code changes. None transfers scientific or source authority.

The experimental treatment is the existing 10,007-row historical Episode
*aggregate*. Individual-action episode memories have not been established
as retrievable. We explicitly avoided claiming the aggregates are repair
examples. This experiment tests only whether providing these facts changes
success on **one** real task. It does not test genuine experience learning.

## Honest evidence limits

- The source summarises system execution states, not relevant actionable
  algorithm-repair experiences. Therefore providing it should not be mistaken
  for a meaningful test of memory retrieval from individual Episodes.
- One deterministic repair Task repeated twice per condition is too small for
  statistical population inference or a general Agent skill claim.
- The experimental recorder retains actual modified solution hashes, model
  identities and native verifier outcomes, but does not retain all agent
  edit bytes or full provider transcripts. Consequently this receipt alone
  cannot independently rerun the four exact repaired candidate files.
  The separate baseline/oracle/known-invalid task quality matrix remains
  fully reproducible through the existing Harness QA.
- Each model call has bounded wall-time; provider token billing and dollar
  prices are not recorded. Observed elapsed time is not financial cost.
- This data does not authorize autonomous Agent production promotion,
  data deletion, policy broadening or live financial effects.

## Business disposition and feedback

**HOLD**: The current historical Episode corpus is suitable for a
source-grounded Research factual answer (prior accepted 20/20 demonstration),
but not qualified for task-level skill improvement based on this experiment.
Do not build a new universal memory service, vector index or evaluation
orchestrator on the strength of these aggregates.

Next consumer-driven data change should be bounded and prospective:
have Runtime/Harness record a *specific successful or failed real task's*
action and independently verified outcome. Use an actual different held-out
task (or controlled variants with different unseen oracle cases) through the
existing Harness dataset/solver/scorer. Only then test whether a relevant
experience improves future task acceptance. This is a data collection
requirement for that concrete consumer, not a claim that the feedback loop
has already autonomously improved production data policy.
