## Overall architectural determination

Ordivon is a **modular multi-Owner monorepo**, not a textbook apps-thin/packages-thick Nx template. Natural Owner roots are independently deployable or evaluable; domain-first vs technical-layer-first alone cannot grade them. Observed architecture already has a canonical Owner manifest, source literal dependency policy, Host/Runtime separate truth, the full R2.1 typed LEGO contract, and native release/verification boundaries. **PARTIAL rather than globally compliant**: documented/current historical claims conflict in some paths, legacy persistence still exists alongside PG, some high-churn functions concentrate multiple different responsibilities, and native literal-source lint cannot prove all dynamic or installed dependency edges. Installing Nx or Turborepo to replace a working Rust/Python/TS mixed-stack source mechanic is **not justified**.

Model: one independently replaceable responsibility is a LEGO, *not* one file or package. The audit relation SourceFile → Current Responsibility → Natural Owner → Actual Evidence/Consumer is diagnostic only; static absence of references does not prove the last edge is empty.

## Directional import-graph counterexample (false-positive prevention)

A temporary read-only Python AST graph resolved 331 source modules and 654 explicit intra-project import edges; it found one syntactic two-node strongly-connected component between domains/capital/src/ordivon_capital/trading/okx_demo_execution.py and okx_official_cli.py. **Source inspection overturns an eager-runtime-cycle claim**: okx_official_cli.py:17–21 imports its base class from the Demo module at module load, while the reverse import appears inside main's conditional official-transport branch at okx_demo_execution.py:399, *not* at module import time. This is a lazy optional-provider dependency, not evidence of an initialization cycle or a need to invent a new shared module. C02 remains PARTIAL for dynamic imports/installed effects; action is **KEEP**, with no speculative refactor. The graph's Python module subset (331) is not all 1,460 tracked Python files, and syntactic edges are not all runtime edges. This is a concrete negative against blindly forcing dependency-graph scores into file moves.

## Root-cause framing and realistic trade-offs

- **Truth/currentness drift** is an information ownership and lifecycle problem, not a lack of ADR files. Historical Work and Agent plans routinely remain readable; promoting them to current authority creates false execution paths.
- **Deep module vs shallow glue** is a *change localization* question. Two 30-line helpers under different Owners need not share code; removing a wrapper that holds a public import contract often makes architecture worse.
- **Local quality vs system boundary**: Owner lint/CI checks source relationships, but actual Runtime effect, installed Gateway schema, Host PG snapshot history and domain semantic acceptance remain separate. No amount of more colored scoring or forced generic hooks proves these external facts.
- **Management cost**: fragmented multi-Agent simultaneous PRs create parallel Spec drift; use one natural Owner and current protected Git branch per affected file. Toyota Lean removes duplicated work; TOC starts at real change/recovery bottlenecks instead of optimizing repository file counts.
- **Decision to deliberately NOT refactor** is a valid architecture outcome. Without an observed consumer or concrete fault, pass on speculative package moves, shared helpers, converting a demo-only SQLite ledger to PG, or installing Nx just to obtain a second graph.

## Relevant official mature patterns (not blanket migrations)

- Nx module dependency constraints and documented literal lint limitations: https://nx.dev/docs/features/enforce-module-boundaries . Ordivon already owns equivalent multi-language source checks for its declared seams; do not duplicate Nx Enterprise conformance.
- Matt Pocock architecture and deep-module deletion test: https://github.com/mattpocock/skills/blob/main/docs/engineering/improve-codebase-architecture.md . Use recent-churn + exact call site before selecting a deepening.
- Superpowers executing plans: https://github.com/obra/superpowers/blob/main/skills/executing-plans/SKILL.md . Reuse isolated source cut, preflight and output readback; don't add tests contrary to the user freeze.
- ECC refactor-clean/quality-gate as optional operator methods: https://github.com/affaan-m/ECC . Foreign hooks or new memory/skill routers are not authorized by this audit.
- Parnas information hiding, Fowler refactoring, DDD Bounded Context, SRE eliminating toil are design disciplines; they do not independently prove an individual file should move.
