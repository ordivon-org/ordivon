# China Student Seed Experiments R3

Date: 2026-09-20
Status: CONCIERGE-ONLY / NO PRODUCT BUILD AUTHORIZED

## 1. Goal

Falsify the strongest R3 seeds using real student behaviour before software investment.

## 2. Minimal cohort structure

Recruit small cohorts from:
- one ordinary undergraduate cohort;
- one competition-active cohort;
- one internship/job-search cohort;
- one 推免/考研 cohort;
- one research/project-active cohort.

Prefer direct access and repeated observation over a large one-shot survey.

## 3. Probe protocol

### P1 — Weekly Radar
Collect only:
university, major, year, goals.

Deliver:
3-10 verified relevant opportunities/obligations per week.

Measure:
open, save, forward, act, apply/register, dismiss, false positive, missed relevant item, follow-up outcome.

### P2 — Eligibility Desk
Student sends a notice/link.

Deliver:
eligible / not eligible / unknown;
rule trace;
missing information;
next action.

Measure:
whether student would otherwise ask a senior/counsellor/search manually;
time saved;
correction rate;
authority confirmation.

### P3 — Notice-to-Action
Student forwards screenshots/messages/official links.

Deliver:
deadline, prerequisites, checklist, reminder, status.

Measure:
completion and whether reminder prevented a miss.

### P4 — Option Map
Map one student's next 12-24 months:
competitions, research, internships, 推免/考研/留学/employment prerequisites.

Measure:
whether it surfaces previously unknown irreversible preparation windows.

## 4. Distribution experiments

Do not start with paid ads.

Test:
- class/major group referrals;
- student-club referrals;
- one shareable "deadline card";
- one shareable "this applies to you" card;
- campus community posts;
- friend-to-friend invite.

Measure qualified retained users, not impressions.

## 5. Monetisation probes

Do not build payment infrastructure solely for the test.

Ask separately:
- would user pay ¥x for a one-time season/workbench?
- would user pay for premium personalized monitoring?
- would an employer/organizer pay for qualified reach?
- would a lab/programme/club sponsor access?
- would a university unit sponsor a bounded cohort?

No advertised price becomes strategy until actual commitment/payment evidence exists.

## 6. Trust tests

Compare:
A. plain AI answer;
B. source-backed answer;
C. source-backed + applicability explanation + unknowns.

Measure which one students trust and act on.

## 7. Noise test

Deliberately vary volume:
- 3 highly filtered items;
- 10 medium filtered items;
- broad feed.

Determine whether compression is the value.

## 8. Kill rules

Kill/narrow if:
- students do not act;
- source maintenance cost dominates value;
- relevance requires intrusive personal data;
- one incumbent already solves the exact job sufficiently;
- users prefer existing groups and do not return;
- users only want cheating/proxy completion;
- no payer path survives.

## 9. Build gate

No dedicated Student product repository/app/backend until one probe shows:
- repeated retained usage;
- action/outcome evidence;
- recurring workflow;
- feasible source/currentness operations;
- clear privacy boundary;
- plausible payer.

Use current Ordivon capabilities and simple delivery channels first.
