# Principles

1. **Reality over representation** — verify the external outcome, not only internal state.
2. **Mature knowledge first** — search human knowledge, standards and mature implementations before inventing.
3. **Composition over ownership** — Ordivon should own as little generic capability as possible.
4. **Build last** — self-build only after configuration, reuse and thin adaptation are shown insufficient on a real task.
5. **Domain standards over private ontology** — use the vocabulary of the relevant discipline whenever possible.
6. **Replaceability** — tools and infrastructure are capability providers, never identity-defining Ordivon components.
7. **Thin common core** — promote semantics to the core only after cross-domain evidence.
8. **Deterministic where possible, agentic where needed** — use workflows/solvers/validators for well-defined work; use agents at uncertainty and translation boundaries.
9. **Evidence over assertion** — completion requires domain-appropriate evidence.
10. **Migration by value, not ancestry** — historical Ordivon concepts receive no preservation privilege.
11. **Profiles, not duplicated platforms** — domains tailor shared mature methods instead of cloning infrastructure.
12. **Learn compositions** — successful problem -> method -> capability -> workflow -> validation relationships are primary long-lived assets.
