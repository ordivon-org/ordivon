# Experimental System Analysis R1

Status: task-local derived analysis over the Experimental Episode PostgreSQL projection.

## Purpose

RW4 asks whether retained experimental experience can answer useful system questions instead of being discarded after a benchmark or test run.

System Analysis R1 separates five questions:

1. Failure: what outcome states and mechanical resource profiles were observed?
2. Cost: which explicit cost or proxy signals exist, and how complete is coverage?
3. Capability: which natural-owner references were observed?
4. Generalization: is an explicit DEVELOPMENT/JUDGE split present?
5. Intervention: is a frozen intervention contract plus explicit assignment present?

## Standing vocabulary

- DESCRIPTIVE_ONLY: the corpus supports a descriptive summary but not causal attribution.
- PARTIAL_COVERAGE: useful signals exist but coverage is incomplete or proxies are not direct cost.
- NOT_IDENTIFIED: the experimental design required for the question is absent.
- ELIGIBLE_FOR_SEPARATE_*_STUDY: prerequisites exist; this analyzer still does not infer the effect.

NOT_IDENTIFIED is a successful analytical outcome when the corpus cannot lawfully support a stronger claim.

## Anti-authority law

The analyzer does not create a capability registry, infer domain success from Runtime resolution, convert artifact/event counts into money, compute a universal fitness score, rank candidates, choose promotion, infer causal effects without a frozen intervention contract, or infer generalization without explicit DEVELOPMENT/JUDGE evidence.

The PostgreSQL store remains a rebuildable analytical projection. Natural owners retain truth.
