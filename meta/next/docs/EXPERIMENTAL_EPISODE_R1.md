# Experimental Episode Binding R1

Date: 2026-09-22
Status: **CANDIDATE / TASK-LOCAL / NOT OWNER TRUTH**

## Purpose

Bind exact owner-native evidence from materially different Ordivon systems into one
deterministic analytical episode without moving execution, cognition, continuity, artifact,
or domain truth into a new control plane.

The first pressure test is historical Runtime R5C because it already contains 10,000
executions plus event/artifact relations. The second required pressure test is Harness
cognitive evidence. PostgreSQL admission is intentionally blocked until both mechanical
and cognitive shapes are understood.

## Identity law

`episodeId` identifies the same experimental episode across later projection enrichment.

`projectionDigest` identifies the exact current analytical projection.

Therefore:

```text
episodeId stable
projection bytes change
=> projectionDigest changes
```

Cross-owner identity is never inferred from timestamps, names, path similarity, or semantic
guessing. Exact IDs, digests, receipts, or explicit bindings are required.

## Authority law

```text
Owner-native evidence = authority
Experimental Episode  = derived analytical projection
```

R1 owns no execution, retry, scheduling, capability availability, domain verdict,
authorization, promotion, or Git truth.

## Sensitive-data law

R1 is deny-by-default. The Runtime R5C adapter does not reproduce raw:

- `workspace_snapshot`;
- `execution_plan`;
- event payloads;
- artifact bytes;
- credentials or secret material.

The exact source run is instead bound by `sourceRecordDigest`. Event and artifact sets are
bound by deterministic set digests over identifiers, metadata, and existing content
digests.

## R5C projection

R5C contributes mechanical execution observations only:

- exact execution identity;
- legacy attempt/workspace references;
- request/operation/plan/result/recovery digests where present;
- execution state/resolution/termination/recovery observations;
- event-set count + digest;
- artifact-set count + digest + byte/truncation counts.

It does not establish semantic task success.

## Admission gates before PostgreSQL

R1 is not sufficient to create an Experimental PostgreSQL database.

Required first:

1. all 10,000 historical R5C executions map one-to-one without identity collision;
2. execution state/resolution distributions are preserved;
3. all historical event/artifact rows are bound;
4. deterministic replay produces the same projection digests;
5. sensitive Runtime payloads do not escape;
6. a second, materially different Harness cognitive adapter validates the abstraction.

Only then may RW3 decide whether a PostgreSQL consumer is justified.
