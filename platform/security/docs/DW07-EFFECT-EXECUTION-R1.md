# DW07 Authority-Bound Effect Execution R1\n\nDate: 2026-10-01\nWork: work:security:dwc-r21:dw07-effect-execution:20261001\n\nDW07 is a thin adapter between a DW06 effect proposal, existing Security effect admission,\nan external natural provider, replay/reconciliation, and an execution receipt.\n\n## Separation law\n\nauthorization != effect admission != provider commit != execution receipt != world consequence.\n\nDW07 stops at provider commit evidence. Every valid receipt carries worldEffectVerified=false.\nDW08 owns later authoritative consequence verification.\n\n## Proposal contract\n\nA DWC effect proposal binds exact case/subject snapshot, request identity, effect type,\nAction/Target/Actuator-style fields, commit point, replay identity, blast radius,\nreconciliation oracle, reversibility/compensation metadata, and the exact DW06 authority\nobligation id/digest.\n\ncompile_effect_request maps that proposal to the existing Security range-effect-request /\neffect_admission.rego waist. It also exposes an optional OpenC2-shaped Action-Target-Actuator-\nArguments projection, but performs no OpenC2 transport and makes no authorization decision.\n\n## Replay and reconciliation\n\nReplayBinding binds one requestId to immutable request content and the original admission.\nExact replay first reconciles by requestId+requestDigest. A committed receipt is returned\nwithout redispatch. Same requestId with changed content fails closed.\n\nTransport failure is never blindly retried:\n\n- if reconciliation finds a committed receipt: return TRANSPORT_LOSS_RECONCILED_UNVERIFIED;\n- if an authoritative reconciliation oracle proves no commit: return RETRY_SAFE_AFTER_AUTHORITATIVE_NO_COMMIT;\n- otherwise: AMBIGUOUS_RECONCILIATION_REQUIRED.\n\n## Receipt contract\n\nA receipt must bind exact request id/digest, effectExecuted=true, worldEffectVerified=false,\npost-write state digest, provider commit ref, commit point, replay identity and compensation ref.\nA provider that self-claims worldEffectVerified=true is rejected.\n\n## R1 acceptance\n\nThe acceptance uses only an in-memory reversible flag provider and the existing OPA\neffect_admission.rego policy. It covers normal commit, exact replay without reapply, changed\ncontent rejection, denied admission with zero provider invocation, transport loss after commit\nwith reconciliation/no retry, and a fixture compensation round trip.\n\nNo OS, network, Security configuration, Runtime service or external resource is mutated.\n
