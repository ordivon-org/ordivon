# Game Development Lenses

Use this Skill when D1-D8 helps reveal a blind spot. Do not use it as a mandatory checklist, lifecycle, ontology, or admission gate.

## Authority

This Skill is **optional and advisory**. It may be removed, ignored, replaced, or partially applied without invalidating a game idea or composition. It must not block creative composition.

## Lenses

- D1 Intent / Audience Context
- D2 Play Causality
- D3 Player Learning / Legibility
- D4 Evidence / Prototyping
- D5 Content / Progression Architecture
- D6 Expression / Feel
- D7 Production Realization
- D8 Product Ecology / Evolution

Treat these as questions, not laws. A game may intentionally omit, invert, blur, or contradict a lens. If the lens stops helping, discard it.

## Use pattern

1. Start from the actual game/mechanic/composition, not from D1-D8.
2. Pick only lenses that may expose a useful question.
3. Record any useful observation as a hypothesis or work item, not as proof that the lens is universally necessary.
4. Prefer direct game evidence, play, teardown, experiments, and external mature practice over framework compliance.
5. Never infer Human experience from machine/synthetic evidence merely because a D-lens was filled in.

## Non-goals

- no required eight-part design document;
- no stage admission;
- no product selection;
- no repository architecture authority;
- no restriction on novel mechanics or combinations.
