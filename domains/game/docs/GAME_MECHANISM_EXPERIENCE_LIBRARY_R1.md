# Ordivon Game Mechanism Experience Library R1

## Purpose

This library sits below the coarse whole-game pattern layer:

```text
Reference teardown
    -> Pattern        broad game-level analogy
    -> Experience     one bounded mechanism interaction / tension / failure / production response
    -> Probe          cheap way to try to falsify transfer
```

Current R1 contains **89 experiences** across **46 reference games/projects** and **374 mechanism tags**.

It is deliberately **Creative-Open**. An Experience is not a recipe, score, best practice mandate, legality gate or product recommendation. It says only: a primary source gives us enough reason to preserve this relationship as an advisory hypothesis worth remembering and testing.

## Evidence boundary

Every record is `SOURCE_GROUNDED_HYPOTHESIS`. Primary developer evidence can establish what a team reports intending, trying, cutting, changing or observing in its project. It does **not** by itself establish Human evidence about enjoyment, comprehension, preference, retention or causal effect.

Therefore every Experience carries:

- mechanisms;
- design problem;
- hypothesized interaction;
- player-decision hypothesis;
- observed project context;
- confounds;
- transfer risks;
- falsifier;
- cheap probe;
- exact KB source refs;
- `canBlockNovelCombination=false`.

## Experience relations

R1 intentionally includes more than synergy:

- **INVERSION** — 4
- **SYNERGY** — 15
- **SUBSTITUTION** — 11
- **LEARNING_SCAFFOLD** — 4
- **REPRESENTATION_COUPLING** — 14
- **FAILURE_MODE** — 10
- **TENSION** — 12
- **PRODUCTION_RESPONSE** — 19

This matters because useful design knowledge is often negative or conditional: a convention was inverted, a feature was removed, two goals pulled against each other, an old rejected idea became feasible only after the surrounding system changed, or production structure constrained what could be designed.

## Examples

- **DOOM**: enemy-bound recovery + forward aggression may substitute for cover/regeneration safety.
- **Factorio**: repeated configuration friction produced shared logistic groups; later substrate changes reopened an idea previously rejected as too complex; full-run play exposed accumulated scope.
- **Baba Is You**: rules represented as manipulable world objects couple spatial puzzle solving to rule mutation.
- **Hades**: run failure + return hub + reactive character memory turns reset into another narrative surface.
- **Tears of the Kingdom**: new ability grammar multiplied by a rich reusable world creates many interaction combinations; consistent affordances protect player causal expectations.
- **RimWorld**: framing the project as a story generator changes what counts as a valuable event or missing feature.
- **Outer Wilds**: curiosity substitutes for explicit mission assignment; knowledge can persist as progression through a resetting world.
- **Against the Storm / Mooncrash / Pacific Drive**: genre is treated as a source of mechanisms to recombine or discard, not a checklist.
- **Saturnalia**: radical changes in scope/perspective/style are retained as production-recovery evidence rather than hidden failure.

## How to use it

When exploring a new composition, retrieve experiences by mechanism tag, relation kind or reference. A match means:

1. inspect the original design problem and observed context;
2. compare confounds and transfer risks;
3. adapt the cheap probe to the new composition;
4. keep the new composition open even if no prior Experience matches;
5. never inherit Human evidence from the reference;
6. promote new experience only after recording its own evidence and failure boundary.

Unknown mechanisms are especially valuable because the library is an experience memory, **not a closed ontology**.
