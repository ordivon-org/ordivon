# Game Product Thesis Sprint R1

## 0. Decision boundary

This sprint does **not** select the first formal game. It converts the now-saturated broad R0 orientation into five falsifiable product hypotheses.

```text
Historical prototype != product candidate
Structural survivor   != player-value proof
Reference success     != causal transfer proof
Existing tooling      != product reason
```

Each thesis must answer:

```text
PLAYER / CONTEXT
PLAYER PROMISE
CORE REPEATED BEHAVIOR
WHY REPEAT IT
MATURE PATTERNS RETAINED
DELIBERATE DIFFERENCE
BIGGEST UNKNOWN
CHEAPEST FALSIFIER
KILL CONDITION
AGENT NEED
```

Agent need defaults to `none` unless a cheaper authored/script/policy/human baseline fails a player-relevant requirement.

## 1. Evidence inherited — and what is not inherited

### External/reference evidence available

Current R0 has already established broad successful reference coverage, including tactical/commitment, sandbox transformation, automation, run/deck strategy, embodied mastery, reactive consequence and player-authored goals. The current decision does not need another broad census.

### Historical local evidence that may update priors

- **D03 epistemic mystery:** structural survivor only when information access is scarce/costly enough that evidence choice changes the solution path.
- **Casefile:** playable epistemic separation and breadth-vs-depth investigation tradeoff were observed; live-model testimony did not materially outperform a cheaper policy/fixed baseline in the tested slice.
- **D05 automation/logistics:** strongest DS1 zero-Agent structural survivor; changing objectives forced different optimal allocations. Human satisfaction/ownership remains unproven.
- **D14 responsive creation:** responsive-other structure survived with deterministic policy; model/LLM necessity was explicitly not established.
- **Station Zero:** commitment, bounded information and delegated consequence can be mechanically real, but rich delegation created substantial interpretation/administration cost. This is evidence about mechanisms and burden, not a mandate to continue Station Zero.
- **D02 tactical puzzle v1:** eliminated because visible telegraphs changed the best action too rarely; any new tactical thesis must increase causal leverage rather than add spectacle or Agent unpredictability.
- **D15 incremental/delegation v1:** demoted because a near-universal early policy made sparse interaction too rote.
- **Echo Hunt:** richer cognition did not beat a cheap adaptive policy in the tested slice; adaptive opposition does not imply expensive cognition.

No historical item above supplies product selection authority.

# 2. T01 — Scarce Evidence / Causal Reconstruction

## Product thesis

A compact investigation game can create repeated value when **information itself is a scarce action resource**: the player decides what to observe, maintains competing causal models, commits actions under uncertainty, and gains new possibilities by revising what they believe rather than by collecting every clue.

### PLAYER / CONTEXT

Solo player; 20–45 minute focused sessions; keyboard/mouse or touch-friendly symbolic interface; player enjoys inference, model-building and fair surprise.

### PLAYER PROMISE

> “I solved it because I understood how the situation worked, not because the game highlighted the answer.”

### CORE REPEATED BEHAVIOR

```text
observe selectively
→ maintain 2–3 live hypotheses
→ spend scarce access to test one distinction
→ commit an action/deduction
→ observe consequence
→ revise model
```

### WHY REPEAT IT

Different causal structures and observation constraints should force different evidence strategies; player knowledge itself becomes progression inside a case.

### MATURE PATTERNS RETAINED

- investigation / causal reconstruction;
- partial information and provenance;
- fair retrospective explanation;
- knowledge changing later action.

### DELIBERATE DIFFERENCE

Do not make clue collection a checklist. Observation opportunities are explicitly scarce, and the chosen evidence must alter reachable actions or confidence enough to matter before final answer submission.

### BIGGEST UNKNOWN

Can scarcity produce satisfying inference rather than frustration or arbitrary withholding?

### CHEAPEST FALSIFIER

One 15–25 minute text/2D case:

```text
1 hidden causal history
3 initially plausible explanations
8 evidence sources
2 inspection choices before first commitment
1 consequence-bearing action
1 later revision opportunity
```

Track whether the player maintains/revises competing models and can explain the decisive evidence relation.

### KILL CONDITION

Kill/rewrite the thesis if most play reduces to:

- inspect the obviously highest-value clue;
- brute-force answer elimination;
- checklist completion;
- guessing because missing evidence is not inferable;
- solving without changing any action based on the inferred model.

### AGENT NEED

`none`. Authored/policy characters are the baseline. Dynamic dialogue is inadmissible until it solves a demonstrated player-value gap.

### Current prior

`PROMISING / HUMAN VALUE NOT YET ESTABLISHED`. Historical evidence is comparatively strong, so this thesis does **not** automatically deserve the first new prototype build.

# 3. T02 — Bottleneck Shifts / Adaptive Automation

## Product thesis

A compact automation game can create sustained systems mastery when goals and perturbations **move the bottleneck**, forcing the player to diagnose why a self-built system fails and intentionally restructure it rather than merely add more production.

### PLAYER / CONTEXT

Solo systems-oriented player; 15–60 minute sessions; mouse-first 2D topology; low narrative dependence.

### PLAYER PROMISE

> “I built this machine, I can explain why it is failing, and I know what redesign I want to try.”

### CORE REPEATED BEHAVIOR

```text
build flow
→ observe throughput / queues
→ diagnose bottleneck
→ redesign topology/allocation
→ new goal or perturbation changes constraints
→ diagnose again
```

### WHY REPEAT IT

The player's own prior solution creates the next problem. Different objectives should turn previously good architecture into a new constraint rather than merely demand more quantity.

### MATURE PATTERNS RETAINED

- Factorio-like automation leverage;
- visible source → transport → processor → sink causality;
- cheap rebuilding and bottleneck feedback;
- self-authored systems.

### DELIBERATE DIFFERENCE

Prioritize **bottleneck migration and redesign** over content volume, giant factories or long technology trees. The smallest product identity is “understand and re-architect a changing system.”

### BIGGEST UNKNOWN

Does spreadsheet-real structural depth become player-visible satisfaction once topology and interaction are added, or does it remain dry optimization?

### CHEAPEST FALSIFIER

One-screen interactive micro-factory:

```text
3 resource types
6–8 machine/transport primitives
3 target objectives
1 perturbation that invalidates a previously strong topology
visible queue/throughput state
free/cheap rebuild
```

### KILL CONDITION

Kill/rewrite if:

- one layout remains near-universal;
- the correct fix is immediately obvious from a single number;
- players improve throughput without being able to explain why;
- redesign feels like repetitive replacement rather than ownership/diagnosis;
- changing objectives produces only scalar capacity increases, not architectural change.

### AGENT NEED

`none`.

### Current prior

`STRONG STRUCTURAL PRIOR / HIGH HUMAN-EVIDENCE VALUE`. D05 is the strongest DS1 zero-Agent survivor, while the exact human-facing transformation remains untested.

# 4. T03 — Sealed Intent / Simultaneous Tactical Commitment

## Product thesis

A small tactical game can create tension and mastery when the player has an **exact model of their own committed plan** but only bounded evidence about an opponent whose actions resolve simultaneously; value comes from prediction, commitment and post-turn causal reconstruction, not from delegation machinery.

### PLAYER / CONTEXT

Solo tactical player; short 10–25 minute encounters; small board; fast reset; direct plan authoring rather than autonomous squad management.

### PLAYER PROMISE

> “I knew exactly what I was committing to; the tension came from what the opponent might do and how our plans collided.”

### CORE REPEATED BEHAVIOR

```text
inspect state/evidence
→ compose own plan
→ preview own consequences
→ commit against uncertain opponent intent
→ simultaneous resolution
→ explain outcome
→ revise next plan
```

### WHY REPEAT IT

Opponent evidence, geometry and commitment windows should continually change which plan is defensible; quick resolution turns errors into new models rather than long punishment.

### MATURE PATTERNS RETAINED

- simultaneous/sealed commitment;
- tactical prediction;
- fast reset and attribution;
- selective uncertainty rather than rule opacity.

### DELIBERATE DIFFERENCE

Strip out Station Zero-style delegated agents and operational dashboards. This thesis asks whether **commitment itself** is sufficient Player Value when the player's own plan is directly authored and perfectly legible.

### BIGGEST UNKNOWN

Can bounded opponent uncertainty preserve meaningful choice without either becoming deterministic puzzle-solving or arbitrary guessing?

### CHEAPEST FALSIFIER

A 6×6 board:

```text
3 player units
2 enemy behavior families
4 direct actions
exact own-plan preview
partial/sealed enemy commitment
6 hand-built states
simultaneous resolution
instant replay/reset
```

### KILL CONDITION

Kill/rewrite if:

- one plan dominates most states;
- own-plan preview trivializes the encounter;
- enemy uncertainty feels random rather than inferable;
- post-turn outcomes cannot be causally explained;
- tension depends mainly on animation/execution spectacle;
- adding delegation would be required merely to create complexity.

### AGENT NEED

`none`. Deterministic/policy opponents are mandatory first baselines.

### Current prior

`HIGH STRATEGIC INFORMATION / CONTAMINATED HISTORICAL EVIDENCE`. A clean micro-prototype can tell us whether prior Station Zero attraction came from tactical commitment or from its accumulated machinery.

# 5. T04 — Responsive Creation / Learnable Audience

## Product thesis

A creation game can become strategically replayable when the player makes a small authored artifact for a **responsive other with hidden but learnable preferences**, so revision is driven by both self-expression and an evolving model of the audience rather than by a visible scoring rubric.

### PLAYER / CONTEXT

Solo creative/strategy player; 10–30 minute rounds; text/2D composition surface; low asset burden in the falsifier.

### PLAYER PROMISE

> “I made something intentionally, learned what this audience responds to, and changed my next creation without surrendering authorship.”

### CORE REPEATED BEHAVIOR

```text
form intent
→ compose under constraints
→ present to responsive audience
→ interpret response
→ update audience model
→ revise/new creation
```

### WHY REPEAT IT

Different audience preferences and responsive interactions should make the same creative vocabulary support different strategies and expressive compromises.

### MATURE PATTERNS RETAINED

- constrained creation;
- revision and authorship;
- another participant's preferences creating consequence;
- learnable responsive opposition/audience.

### DELIBERATE DIFFERENCE

No generative content faucet and no LLM requirement. The audience begins as deterministic responsive policy with hidden learnable preferences. The experiment asks whether adapting to another mind is itself enjoyable.

### BIGGEST UNKNOWN

Will players experience this as authorship plus social inference, or merely reverse-engineer a scoring function?

### CHEAPEST FALSIFIER

A 10–15 minute composition game:

```text
6 motifs/primitives
4 choices per artifact
3 deterministic responsive audience personas
hidden preference + novelty/repetition response
2–3 creation rounds
save/compare revisions
```

### KILL CONDITION

Kill/rewrite if:

- optimal play becomes motif spam or obvious rubric exploitation;
- players stop articulating their own creative intent;
- audience feedback is too opaque to learn or too transparent to be interesting;
- revision is only score optimization, not expressive compromise/adaptation;
- a static rubric produces essentially the same experience.

### AGENT NEED

`none` at R1. A model Agent is admitted only if claim-specific evidence shows that interpretation/generalization beyond the cheapest adequate authored/script/policy baseline is central and materially valuable. Structural, strategy, robustness or causal-control claims may use formal, synthetic, telemetry or controlled-experiment evidence when those carriers identify the claim best; actual Human experience, preference, meaning or comprehension claims still require relevant Human participant evidence.

### Current prior

`STRUCTURAL SURVIVOR / HUMAN EXPERIENCE UNKNOWN`. D14 already proved that responsiveness can exist without an LLM; the missing evidence is whether the interaction is actually worth repeating.

# 6. T05 — Visible Mastery / Precision Movement

## Product thesis

A minimal direct-control game can create strong repeat value when failure is immediately attributable, retry is nearly free, and a tiny movement vocabulary supports visibly better timing, routing and risk-taking within minutes.

### PLAYER / CONTEXT

Solo player; 30-second to 3-minute attempts; keyboard/controller; 2D graybox sufficient for the first falsifier.

### PLAYER PROMISE

> “I can feel myself getting better, and the next attempt is mine to improve.”

### CORE REPEATED BEHAVIOR

```text
read space/timing
→ commit movement
→ succeed/fail with immediate attribution
→ instant retry
→ change timing/route
→ attempt a harder/faster line
```

### WHY REPEAT IT

A small stable verb set should support growing precision and optional risk; mastery is carried primarily in the player rather than unlock systems or content accumulation.

### MATURE PATTERNS RETAINED

- precision movement / timing;
- fast failure/retry;
- safe versus expressive/fast routes;
- legible improvement.

### DELIBERATE DIFFERENCE

This thesis is deliberately **low-system and low-Agent**. It exists partly as an anti-bias control against Ordivon's tendency to prefer information-rich/system-heavy designs.

### BIGGEST UNKNOWN

Can our implementation produce sufficiently clean feel/feedback that we can test mastery without mistaking control defects for a weak thesis?

### CHEAPEST FALSIFIER

Three Godot graybox rooms:

```text
move + jump + one secondary movement modifier at most
room 1: basic timing
room 2: moving/collapsing constraint
room 3: safe route vs faster/riskier route
instant reset
no score/meta rewards in primary condition
```

### KILL CONDITION

Kill/rewrite if:

- improvement is mostly memorizing one scripted timing;
- failures are blamed on collision/camera/input ambiguity;
- players do not voluntarily retry after completion or near-miss;
- safer/faster routes do not create meaningful self-selected challenge;
- the experience only becomes interesting after adding progression/reward layers.

### AGENT NEED

`none`.

### Current prior

`LOW LOCAL EVIDENCE / HIGH ANTI-BIAS VALUE`. This thesis is retained specifically so the portfolio does not collapse into analytical/systemic play simply because Ordivon measures those forms well.

# 8. First experimental wave — admitted

The best next wave is chosen by **marginal information**, not product preference.

## E1 — T03 Sealed Intent micro-tactics — BUILD NEW

Why first:

```text
very cheap carrier
+ strategically important historical confound
+ cleanly strips Station Zero delegation/Agent machinery
+ negative result can prevent major sunk-cost recurrence
```

Goal: determine whether exact own-plan legibility + bounded opponent uncertainty + simultaneous commitment creates interpretable plan revision by itself.

## E2 — T02 Bottleneck Shifts micro-factory — BUILD NEW

Why now:

```text
strongest DS1 structural survivor
+ direct pairing with current Factorio reference-learning lane
+ critical unresolved transformation: spreadsheet structure -> Human systems mastery
```

Goal: determine whether players actually diagnose and intentionally redesign rather than merely chase throughput numbers.

## E3 — T05 Visible Mastery graybox — BUILD NEW

Why now:

```text
portfolio diversification
+ low dependence on historical Ordivon machinery
+ tests whether our discovery method can evaluate embodied mastery, not only analyzable systems
```

Goal: establish a clean Human baseline for direct-control mastery and expose whether control/feel tuning burden is acceptable.

### Why T01/T04 are not in the first new-build wave

- **T01** already has Casefile plus D03 structural evidence and an existing investigation proof packet. The next efficient action is to reuse/repair a suitable existing Human apparatus or author one fresh case only if the old carrier cannot answer the new scarce-observation thesis. Do not rebuild by reflex.
- **T04** has strong DS1 structural apparatus and can enter Human play once an appropriate player-facing carrier is confirmed. Its next need is Human authorship/adaptation evidence, not another structural simulation.

Thus the portfolio uses old work where it actually reduces uncertainty and builds only where a clean experimental carrier is missing.
