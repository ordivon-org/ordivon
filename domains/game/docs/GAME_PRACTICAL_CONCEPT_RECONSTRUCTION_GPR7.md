# Ordivon Game — GPR7 Challenge / Failure / Recovery / Mastery Practical Toolkit

## 0. Scope

GPR7 is the first practical reconstruction round **not** inherited from R0's six original priority clusters.

It was admitted only after the R0-GPR6 closeout re-scanned the complete frozen GDF0-GDF3 substrate and found one material omission:

```text
Challenge / Failure / Recovery / Mastery
```

The frozen semantic owner is GDF2:

```text
ChallengeAssessmentContract
FailureRecoveryContract
MasteryClaimContract
```

GPR7 asks a narrower practical question:

> Which Human/Agent/research/UI abstractions are useful enough to recover above those foundations without recreating scalar Difficulty, universal Failure, one Recovery ontology or a Mastered state?

GDF0-GDF3 remain frozen.

---

# 1. Starting null models

GPR7 begins deletion-first.

```text
N1:
Difficulty can remain an ordinary scalar/label.
No generic practical challenge view is needed.

N2:
Failure can remain one status word.
Scope can stay implicit.

N3:
All recovery concepts can share one practical Recovery abstraction.

N4:
System mastery can remain product prose.
No source-backed mastery view is needed.
```

These are not strawmen. If they survive real current consumers and cross-Game pressure, GPR7 should add nothing.

# 2. Final null-model verdict

```text
N1 → FALSIFIED
N2 → FALSIFIED
N3 → FALSIFIED
N4 → PARTIALLY SURVIVES FOR CURRENT IMPLEMENTATION
     BUT FAILS AS A GENERAL TOOLING RULE
```

This asymmetry is important.

GPR7 does not conclude that every recovered concept deserves current runtime implementation.

# 4. Why scalar Difficulty fails practically

Station Zero already performs multiple matched challenge analyses:

```text
14 Turns vs 20 Turns
3 objectives × 3 postures × 2 formations
baseline vs topology treatments
pressure interventions
knowledge conditions
enemy doctrine changes
objective-bearing placement changes
```

These comparisons produce different answers depending on the question.

One treatment may:

```text
reduce Rescue viability
increase Core viability
change selected actions
leave another objective unchanged
```

There is no safe single number that preserves all of those relations.

Therefore:

```text
Difficulty/Challenge != intrinsic content scalar
```

has immediate practical value.

---

# 5. `ChallengeAssessmentView`

GPR7 stabilizes:

```text
ChallengeAssessmentView
```

as a **derived query-specific view**.

It does not answer:

```text
How difficult is content X, universally?
```

It answers:

```text
Under this evaluation target,
for this attribution target,
under these conditions/horizon/currentness,
what challenge property is actually established?
```

---

# 6. Challenge query scope

A correctness-critical challenge query may need:

```text
evaluation criterion
criterion authority / provenance / currentness
attribution target
Game/practice state and rules
horizon
control / observation / access configuration
history / knowledge
opponent / team condition
stochastic / exogenous condition
requested projection kind
evidence / identification assumptions
```

Not every UI needs to display all of this.

But drill-down must preserve it when the claim matters.

---

# 7. Challenge projection kinds

GPR7 permits query-specific projections such as:

```text
outcome distribution
feasibility / reachability
capability threshold region
capability discrimination / sensitivity
outcome risk
opponent-conditioned outcome
recovery / consequence cost
continuous quality / progress
owner-local custom projection
```

No projection is universal Difficulty.

---

# 8. The central challenge separation

```text
OutcomeProbability
!= CapabilityThreshold
!= CapabilityDiscrimination
!= OutcomeRisk
!= RecoveryCost
```

A lottery can have high failure probability and no meaningful skill sensitivity.

A rhythm chart can require high precision but have cheap instant retry.

An easy action can carry catastrophic consequence.

An impossible task can fail to discriminate higher skill at all.

The practical view must therefore state what it measured.

---

# 9. Human-friendly difficulty labels can still exist

GPR7 does **not** ban:

```text
Easy
Normal
Hard
Expert
```

or numeric local difficulty settings.

They can remain excellent authoring/UI vocabulary.

But a cross-Game correctness-critical tool must treat them as:

```text
lossy label over an owner-local declared projection / policy
```

not as an intrinsic scalar truth.

So:

```text
DifficultyLabel != ChallengeSourceOfTruth
```

---

# 10. Identification status belongs in the practical view

GDF2 showed that challenge structure is often underidentified.

GPR7 therefore exposes practical epistemic states such as:

```text
structurally_proven
intervention_identified_under_assumptions
estimated_under_declared_model
bounded_only
unidentified_or_multiple_explanations
```

These are methodology vocabulary, not ontology.

Their purpose is to stop an Agent or dashboard from turning weak aggregate evidence into a stronger causal claim.

# 11. `ChallengeComparisonView`

Current Station Zero makes comparison at least as important as absolute challenge description.

GPR7 therefore separately stabilizes:

```text
ChallengeComparisonView
```

It consumes:

```text
baseline condition
comparison condition(s)
changed dimensions
held-fixed dimensions
attribution target/population
projection kind(s)
evaluation scope
evidence
```

and reports per-projection differences.

---

# 12. Why comparison is separate

A useful product statement is often:

```text
20 Turns makes the Rescue commitment reachable
under several current policy basins
where 14 Turns did not.
```

That is stronger and safer than:

```text
20 Turns is easier.
```

Likewise:

```text
cover-choke preserves Rescue viability
but changes Core/Hive action/outcome surfaces
```

is more informative than one difficulty delta.

---

# 13. Challenge does not require a total order

Two conditions can be incomparable.

Example:

```text
Condition A:
lower capability threshold
higher failure consequence

Condition B:
higher capability threshold
cheap retry
```

There need not be one universal answer to:

```text
Which is harder?
```

unless the user supplies a declared weighting/purpose.

---

# 14. Assistance does not equal inverse difficulty

An accessibility remap or assist can:

```text
remove one capability demand
preserve another
expose a new higher-order demand
change attribution target
change control contribution topology
```

Therefore:

```text
AssistLevel != InverseDifficultyByIdentity
```

This matters directly for Agent-assisted and shared-control GameForms.

---

Current Station Zero already uses them extensively.

But:

Human felt difficulty remains Human-owned evidence.



# 22. Action failure is not pursuit failure

Station Zero action feedback exposes:

```text
executed
interrupted
invalidated
contested
no_effect
```

An action can be contested and the mission later succeed.

A no-effect action can be rationally retried after state changes.

Therefore:

```text
ActionAttemptResolution
!= FailureAssessmentByIdentity
```

Action feedback is evidence about local execution, not a universal failure state.

---

# 23. Terminal reason is not failure cause

This is one of GPR7's strongest current-product findings.

Station Zero sets encounter/faction outcome reason from:

```text
turn_limit
no_active_combatants
```

These correctly answer:

> Why did this encounter horizon terminate?

They do **not necessarily answer**:

> What caused the Rescue commitment to fail?

For example:

```text
terminal reason = turn_limit
```

while evidence may show:

```text
zone capacity contention
late objective focus
resource loss
blocked route
Agent realization variance
```

as contributors.

So:

```text
TerminalReason != FailureCauseByIdentity
```

is now a practical architecture law.

GPR7 stabilizes:

```text
OutcomeAttributionView
```

as a derived evidence-bounded attribution view.

Its job is not to generate a satisfying story.

Its job is to expose what the evidence supports.

Possible contributor classifications:

```text
causally_established_under_declared_probe
strongly_supported_contributor
enabling_or_constraining_condition
correlated_or_temporal_only
excluded_by_current_evidence
unresolved_candidate
```

```text

```

A Human/Agent explanation can summarize evidence, but cannot upgrade an unresolved candidate into a cause merely because the prose is coherent.

# 37. `PursuitContinuationView`

The view asks:

> After this outcome/assessment, what authoritative continuation transitions remain relative to this pursuit and horizon?

Possible option kinds:

```text
continue_current_state

revive
full_reset
team_rescue
```

# 38. Continuation must expose preservation/loss

Different continuation transitions may preserve or lose:

```text
state
resources
history / progress
information
time / opportunity
pursuit identity
```

This matters more than the label `retry` or `reset`.

---

# 39. Retry does not erase history

A checkpoint reset can restore World state while retaining:

```text
historical fact that the prior attempt happened
player knowledge
meta progression
audit/replay history
```

Therefore:

```text
Retry != HistoryErasure
Reset != HistoryErasureByIdentity
```

This aligns with GPR4's anti-history-erasure laws.

---

# 40. Continuation is not rollback by identity

A failed route may lead to:

```text
alternate route
new objective
future-only continuation
compensating meta progression
```

without restoring the old state.

Thus:

```text
Continuation != RollbackByIdentity
```

---

# 41. GPR4 Remedy remains different

GPR4 Remedy means corrective work in response to:

```text
reversal
execution error
over-enforcement
recognized harm
```

GDF2 pursuit continuation means:

```text
what play/practice continuation remains after an outcome
```

Therefore:

```text
InstitutionalRemedy
!= PursuitContinuationByIdentity
```

They may interact, but must not collapse.

---

# 42. Terminality becomes a query

GPR7 retains GDF2's elegant result:

```text
Terminality
```

does not need an independent primitive.

Ask:

> Under the current pursuit identity and horizon, does any authoritative continuation preserve pursuit of the same commitment?

So:

```text
NoContinuation != MaximumChallenge
Failure != Terminality
```

# 53. Criterion circularity is a real risk

Unsafe:

```text
observe target performs pattern X
→ define mastery as performing pattern X
→ cite same performance as proof of mastery
```

The criterion/probe region must have independent provenance or be validated through held-out/independent transformations.

So:

```text
PerformanceEvidenceCannotDefineItsOwnMasteryCriterionCircularly
```

---

# 54. Saturation weakens mastery evidence

A player can achieve:

```text
zero errors
```

on an easy saturated condition that no longer discriminates relevant capability.

Therefore:

```text
ZeroError != BroadMastery
ObservedPlateau != SkillCeiling
```

A `MasteryEvidenceView` should surface saturation warnings where supported.

---

# 55. Task-specific mastery is legitimate

GPR7 does not require every mastery claim to include broad transfer.

A speedrunner can legitimately have:

```text
mastery of patch/category X
```

without mastery of:

```text
another patch
another game
another category
```

Thus:

```text
TaskSpecificMastery != TransferMastery
```

but task-specific mastery is not inferior or invalid.

---

# 56. Currentness matters

Patch, rules, opponent distribution, mapping, assistance or evaluation can change.

Old mastery evidence remains historically true for its old condition.

It does not automatically remain current.

Therefore:

```text
CurrentMasteryRequiresCurrentOrTransferredEvidence
```

A view may report:

```text
stale_or_transfer_unestablished
```

instead of deleting historical evidence.

---

# 57. Human-Agent shared control forces attribution discipline

If:

```text

```

then a legitimate claim may be:

```text

```

But not automatically:

```text
Human-independent mastery
```

Strong:

```text
JointControllerMastery != HumanIndependentMastery
```

---

# 58. Synthetic mastery is legitimate for the synthetic target

A deterministic or learned synthetic policy can satisfy a declared criterion robustly across controlled probes.

That can support:

```text

```

But:

```text
SyntheticControllerMastery != HumanMastery
```

and it does not establish Human felt difficulty or competence.

---
