# External theory / method pressure on Ordivon Book v0

Status: `COMPARATIVE PRESSURE / NO EXTERNAL THEORY OWNS ORDIVON STANDING`

The purpose of this comparison is subtraction and repair. A mature external theory is imported when it removes a blind spot or prevents Ordivon from re-proving a solved structure. It is not imported merely because terminology is similar.

## Pressure matrix

| External line | What it contributes | Book v0 consequence | What Ordivon does **not** import |
| --- | --- | --- | --- |
| Zhang & Norman, *Representations in Distributed Cognitive Tasks* (1994) | Internal and external representations jointly shape task cognition; representation format changes what information and procedures become available | Treat Book form/order as part of cognition, not neutral storage; test whether a fresh consumer can recover the right distinctions | no claim that every external artifact is part of one literal mind |
| Kirsh & Maglio, *On Distinguishing Epistemic from Pragmatic Action* (1994) | Some actions change the world to make cognition easier rather than directly advancing an external goal | Writing/integration can be an epistemic operation: reorganizing representations may reduce future search/reconstruction cost | no assumption that textual reorganization alone changes domain truth |
| Clark & Chalmers, *The Extended Mind* (1998) | External stable resources can function as standing cognitive resources under some conditions | Book is designed as a recoverable external cognitive surface for Human/Agent use | no need to settle the metaphysical extended-mind thesis |
| Dewey, inquiry / pragmatism | Inquiry begins from an indeterminate/problematic situation; problem formulation and hypothesis testing participate in transforming the situation | Keep Reality pressure and problem formation before fixed theory; action/test belongs inside the inquiry loop, not after knowledge is complete | no single five-step universal workflow; Ordivon keeps owner/authority/currentness distinctions Dewey does not supply |
| Bayesian epistemology / confirmation theory | Evidence can rationally change graded confidence; evidence rarely forces one hypothesis uniquely | Preserve evidence→standing update as a distinct operation and keep rivals/underdetermination visible | no universal requirement that every Ordivon standing be a scalar probability |
| Popper/Lakatos/Kuhn family | Falsification pressure matters; isolated hypotheses are often embedded in programmes/auxiliaries; scientific change is not simple cumulative truth addition | Preserve hostile falsifiers, genealogy, rejected repairs, and research-programme-level change; do not write history as smooth accumulation | no single demarcation rule, no fixed hard core, no assumption that every anomaly should trigger immediate abandonment |
| Argyris, double-loop learning | Error correction may require changing governing policies/objectives rather than only actions under fixed rules | Book revision may challenge the representation, evaluator, goal/authority assumption, or update rule—not just the local answer | no collapse of normative authority into a generic learning loop |
| Living systematic review practice (Cochrane) | A living synthesis needs a question worth keeping current, consequential new evidence, explicit update status/triggers, and an exit condition | Book updates are trigger-driven, source-fenced, and may legitimately produce NO_CHANGE; no ritual calendar rewrite | no claim that Book is a systematic review or that review methodology owns domain truth |
| PRISMA 2020 | Transparent reporting of search/selection/synthesis methods makes a synthesis auditable | Source map and explicit synthesis ceiling accompany the prose | no checklist-as-quality scalar and no forced biomedical review structure |
| W3C PROV | Derivation, revision, primary source, activity, and agent can be represented without treating the latest artifact as timeless identity | Treat a Book revision as derived from exact source fences; preserve Git history and explicit source bindings | no PROV ontology/schema implementation until a real machine consumer earns it |
| Diátaxis | Explanation, tutorial, how-to, and reference serve different user needs | Book is primarily explanation/current-model projection; operational manuals and API reference stay with their owners | no demand that every Book chapter fit a documentation template |
| Early-modern commonplace-book practice | External excerpts, indexing, thematic recombination, and long-term note keeping extend memory and reuse | Book may consume indexed fragments, but must add integration rather than becoming a commonplace dump | no equation of collected fragments with coherent current understanding |

## Design conclusions after subtraction

1. **Book is an epistemic instrument, not just documentation.** Its representation can change what a finite consumer can discriminate and recover.
2. **Update is not identical to accumulation.** A mature revision can delete, narrow, reframe, or record `NO_CHANGE`.
3. **Evidence update is not action authority.** Bayesian/confirmation thinking helps on evidential change; Ordivon still requires owner/normative/action-specific authority.
4. **Falsification is not one-shot theory deletion.** Lakatos/Kuhn pressure the Book to preserve auxiliary assumptions, genealogy, and regime changes rather than a heroic sequence of correct answers.
5. **Learning can target the loop itself.** Argyris-style double-loop pressure supports revising representations, evaluators, policies, or problem formulations, but does not let learning mint authority.
6. **Living does not mean continuously edited.** Triggered revalidation with explicit source fences is enough until stable-edition consumption appears.
7. **Provenance need not become ontology.** Git + source bindings + claim paths are the smallest current solution.

## External source notes

Primary/authoritative comparison surfaces used during this pilot include Stanford Encyclopedia of Philosophy entries on Bayesian Epistemology, Confirmation, Scientific Method, Lakatos, Dewey and Pragmatism; Harvard Business Review's Chris Argyris articles on double-loop learning; Cochrane Handbook material on updating/living systematic reviews; PRISMA 2020; W3C PROV-O/PROV-DM; Diátaxis documentation theory; and Cambridge/Harvard collections on commonplace-book history.

These sources pressure Book design. They do not confer current Ordivon standing.
