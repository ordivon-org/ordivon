# Future Horizon — 从软件中的 Ordivon 到 Reality 中的实验智能

Status: `USER-ADOPTED LONG-TERM GOAL / NON-AUTHORITATIVE FUTURE HORIZON`

Adopted: `2026-08-25`

This document records a long-term direction chosen by the user. It is a **goal and design horizon**, not evidence that the described capabilities already exist, not a new semantic owner, and not an obligation to build every layer named below.

---

## 0. 为什么把它记录成 Future Horizon，而不是“第六章结论”

Ordivon Book 当前的责任是把已经存在的 standing、跨 owner synthesis、practice 与 consequence 编译成有限智能可消费的整体模型。

这份文本的 epistemic class 不同。

它记录的是一个已经明确选择的长期方向：

> **未来当 Ordivon 拥有自己的实验室后，让它从主要存在于软件中的 intelligence substrate，逐步扩展为能够直接观察、测量、实验、作用于物理 Reality，并把 consequence 重新纳入 cognition 的 experimental intelligence substrate。**

因此必须保留：

```text
Goal
!=
Current capability
!=
Prediction
!=
Guaranteed roadmap
```

这份 Horizon 的作用不是证明未来一定如此，而是让未来 Human / Agent 在做实验室、Workstation、Host、Runtime、Harness、World、Security、Media、Game、Interlocus 等决策时，知道存在这样一个长期方向，并能判断某个局部工程是否真正增加了通往它的 capability。

## 1. 核心目标：让 Ordivon 从信息消费者变成证据生产者

今天 Ordivon 的多数 Reality contact 仍然经过别人已经建立的数字接口：

```text
Internet
API
OS telemetry
market data
files
logs
web pages
external databases
third-party instruments / services
        ↓
     Ordivon
```

这使 Ordivon 可以做大量研究、判断、软件行动与数字世界中的闭环，但 Observation Interface 的很大一部分仍然由外部系统决定。

实验室真正重要的变化不是“多了硬件”，而是：

```text
Reality
  ↓
Ordivon chooses what to measure
  ↓
Measurement / experiment design
  ↓
Evidence
  ↓
Standing
  ↓
Physical intervention
  ↓
Consequence
  ↓
New measurement
  ↓
Revision
```

于是一个未知问题不再只能得到：

```text
search more information
reason harder
wait for external evidence
```

还可以得到：

```text
design a discriminating experiment
change the observation basis
build an instrument
intervene on Reality
produce new evidence
```

这是这一长期目标最重要的 capability transition：

```text
Information consumer
→
Evidence producer
```

以及：

```text
Software action
→
Reality intervention
```

## 2. Ordivon 的边界不再以 software 为天然终点

当前实现 substrate 仍然主要是 software。

但 owner 的 responsibility domain 不需要与实现层重合。

未来实验室允许 Ordivon 沿以下层次扩展：

```text
Human / Agent
      │
      ▼
Ordivon cognition / coordination
      │
      ▼
Application / software
      │
      ▼
Operating systems / services / drivers
      │
      ▼
Firmware / BIOS / UEFI / EC / BMC
      │
      ▼
Embedded electronics / MCU / FPGA / PCB
      │
      ▼
Sensors / instruments / buses / power
      │
      ▼
Robotics / actuators / mechanisms
      │
      ▼
Fabrication / automated test / physical experiment
      │
      ▼
Reality
```

但这不是一条要求逐层“占领”的 roadmap。

真正的扩展原则是：

> **只有当某一层阻止有限智能获得重要的 observation、discriminability、action、recovery、authority、continuity 或 consequence feedback 时，才由 capability pressure 驱动向该层深入。**

因此：

```text
Lower-level
!=
More important

Own more layers
!=
More capable

Self-built
!=
Better
```

如果成熟外部设备、标准、OS、BMC、机器人平台或实验仪器已经提供了足够好的 capability，Ordivon 应优先消费它们，而不是为了“全栈”复制已有工业体系。

---

## 3. 第一条扩展轴：Machine Reality

距离当前 Ordivon 最近的实验室扩展，是把“计算机本身”从一个大致由 OS/API 表示的对象，变成可以跨软件—固件—电气层联合观察的 Reality。

今天一个黑屏、死机、功耗异常或 sleep/wake failure 往往只能通过：

```text
Windows event
GPU / chipset driver state
ACPI exposure
BIOS version
software telemetry
behavioral reproduction
```

来推断。

实验室化以后，可能加入：

```text
power rail measurement
thermal imaging
logic / bus observation
panel / display signal observation
EC / firmware trace
external watchdog
independent timestamped telemetry
```

然后把多个 locus 时间对齐：

```text
OS event
GPU state
EC state
power transition
physical display consequence
```

这会把很多“软件猜测”转化为更强的 causal discrimination。

长期目标不是让 Workstation 变成一个 BIOS 工程项目，而是让它能够在必要时跨层回答：

> **这台机器的真实状态是什么？哪个 layer 的 transition 导致了当前 consequence？**

---

## 4. 第二条扩展轴：自己制造 Reality Interface

当现有 instrument 或 API 无法提供需要的 measurement basis 时，Ordivon 应能够逐步设计自己的观测与控制节点。

可能的 substrate 包括：

```text
MCU
FPGA
ADC / DAC
I²C / SPI / UART / CAN / USB / Ethernet
custom sensors
power measurement
synchronization / timestamping
firmware
PCB
```

例如一个实验需要同时观测：

```text
16-point temperature
current / voltage
vibration
fan / motor state
software events
```

Ordivon 不必被一个现成产品的 schema 限制，而可以形成一个 task-specific instrument。

这使 Harness 的长期含义可以从：

```text
Tool Harness
```

扩展到：

```text
Reality Instrument Harness
```

即 Human / Agent 面对的不是寄存器、串口命令和供应商 SDK，而是 source-fenced 的 semantic operations，例如：

```text
observe_temperature()
observe_power()
calibrate()
set_sample_rate()
run_experiment()
```

底层仍可由不同仪器、firmware 与 protocol 实现。

---

## 5. 第三条扩展轴：Physical Host / Out-of-band Continuity

Host 今天主要承担 semantic continuity：让 Agent replacement、context loss、时间跨越之后仍能恢复工作状态，而不伪造 current truth。

实验室提供一个重要的新压力：

> 如果主 OS、Agent process、network 或 compute node 本身失效，continuity 谁来承担？

未来可能出现一个独立于主计算路径的 physical host controller / management plane，负责：

```text
power state
watchdog
out-of-band telemetry
reboot / recovery
crash-adjacent physical logs
UPS / battery
thermal emergency handling
instrument safe-state
```

这不意味着 Host 必须自己实现一个 BMC。

更稳定的目标是：

```text
Agent continuity
+
Compute continuity
+
Physical experiment continuity
```

在主 cognition substrate 消失时，仍保留足够事实，使未来 Agent 可以知道：

- 发生了什么；
- 哪些状态仍有效；
- 哪些状态只是历史；
- 哪些实验需要安全终止；
- 哪些 action 已经产生物理 effect；
- 哪些 effect 仍然 unknown。

---

## 6. 第四条扩展轴：Robotic Action / Embodiment

机器人、运动平台、自动夹具和执行器会改变 Ordivon Action 的基本形态。

今天常见 action 是：

```text
write file
call API
execute process
send request
submit order
```

未来可以包括：

```text
move
pick
place
connect
press
rotate
align
inspect
assemble
replace
measure
repeat
```

于是：

```text
Intent
→
Authorized physical action
→
Physical effect
→
Observed consequence
```

成为 Ordivon 的一等问题。

这会给 Runtime、Security、Normative、World 与 Interlocus 带来比纯软件环境更强的 Reality pressure，因为物理 action：

- 往往不可完全回滚；
- 有惯性和延迟；
- 可能伤害设备、人或环境；
- observer 与 actuator 可能失配；
- execution success 不等于 desired effect；
- physical state 可能在数字系统之外继续演化。

因此 physical embodiment 必须比普通 API automation 更严格地区分：

```text
Capability
!=
Authority
!=
Commitment
!=
Execution
!=
Effect
!=
Consequence
```

## 7. 第五条扩展轴：Automated Experimental Laboratory

当 measurement、instrument control、robotic action、artifact capture 与 continuity 足够成熟后，Runtime 可以承载的不再只是 computation Job，而是一个完整的 Experiment episode。

例如：

```text
Question:
Why does PCB revision V7 reset above 85°C?

Atlas
→ recover prior hypotheses / failures

World
→ establish current board / firmware / instrument state

SCD
→ structure rival hypotheses

PPD / Research
→ find discriminating pressure

Runtime
→ admit experiment

Harness
→ control chamber / PSU / scope / JTAG / sensors

Physical experiment
→ produce traces / video / telemetry / failure

Interlocus
→ bind physical board ↔ firmware ↔ trace ↔ experiment

Security
→ validate measurement / identity / provenance

Standing revision
→ retain / reject / narrow / reopen
```

这里 Runtime 的 durable object 可以逐渐出现 physical-experiment semantics：

```text
setup
calibration
inputs
execution
measurements
artifacts
anomalies
cleanup
provenance
recovery
```

但只有在真实 repeated pressure 出现后，才应该把这些抽象提升为 Runtime 核心结构。

---

## 8. 第六条扩展轴：Fabrication / Physical Artifact Creation

实验室还可能把 Representation → Artifact 的链缩短。

可能包括：

```text
CAD → 3D print
schematic → PCB
mechanical design → CNC / laser / machining
firmware → embedded device
robotic fixture → automated assembly / testing
```

真正重要的指标不是“我们拥有多少制造设备”，而是：

> **一个 hypothesis 所需要的新 physical artifact，能否在足够低的 transaction cost 下进入同一个 cognition–experiment–revision loop？**

这会改变 Computational Possibility / Search Geometry：

过去因为制造成本过高而不可达的实验分支，可能变成当天就能验证的 hypothesis。

因此 fabrication capability 本身会改变 reachable problem space。

## 9. 各 owner 在这个 Horizon 中可能发生什么变化

这份 Horizon 不预先重写 owner 边界，但可以记录未来 pressure 可能把哪些 responsibility 推向新的形态。

### World

从主要消费外部数字 Reality，扩展到管理：

```text
sensor state
calibration state
physical state estimation
measurement uncertainty
observer identity
cross-sensor consistency
```

World 的关键问题会变成：

> 当前可行动的 physical Now 是什么？

### SCD

从 representation / structural distinction 研究，进一步面对：

```text
raw signal → feature → causal variable
multi-modal alignment
measurement basis selection
experimental representation
```

Representation 不再只是信息表达；它可以直接决定哪些物理机制可被看见。

### Harness

从 Tool / Agent capability interface 扩展为：

```text
Agent ↔ instrument
Agent ↔ robot
Agent ↔ embedded device
Agent ↔ experiment
```

但仍应保留 source truth 与 authority conservation，而不是让一个 convenient semantic Tool 自动获得物理行动权。

### Runtime

从 computation / Workspace / Job / Attempt / Artifact，向可恢复的 experiment execution substrate 延伸。

重要的新 distinction 会包括：

```text
command delivered
!=
actuator moved
!=
physical effect occurred
!=
target consequence achieved
```

### Host

从 semantic continuity 延伸到 physical system continuity 与 out-of-band recovery。

### Interlocus

会获得一个非常具体的新任务：把数字 lineage 与实体物体绑定。

例如：

```text
PCB #A17
↔ schematic commit
↔ BOM
↔ firmware build
↔ calibration
↔ experiment run
↔ oscilloscope trace
↔ failure standing
```

### Security

从 cybersecurity 向 `Reality integrity` 扩展。

一个数值“82.3°C”是否可信，不只取决于数据库权限，还取决于：

```text
which sensor
where installed
which calibration
which ADC
which firmware
which timestamp
whether wiring changed
whether the physical sensor is the claimed device
```

因此长期 Security pressure 是：

```text
Trustworthiness of Reality Binding
```

### Atlas

长期应能够保存的不是“实验文件很多”，而是实验文明的 capability lineage：

```text
what was tried
what failed
why the current design exists
what remains open
what must not be trusted
which physical artifacts carried which standing
```

### Media

在实验室中，Media / Representation 可能成为 instrumentation 的一部分。

同一个实验的：

```text
video
thermal image
waveform
software trace
power
motion
human annotation
```

如果不能时间对齐并形成合适 representation，真实 causal relation 可能对 Agent/Human 都不可见。

因此：

```text
Representation
can become
Measurement capability
```

### Game

Game 可以从 synthetic world transition authority 延伸到 synthetic–physical environments：多机器人、多 Agent、真实资源、真实传感器、真实 failure。

这会让 Game × Security × Normative 的 institution / adversary / incentive 研究获得真实 consequence。

### Normative

Physical autonomy 会迫使 Normative 更明确地区分：

```text
permission
consent
safety constraint
institutional authority
physical capability
emergency stop authority
```

尤其不能因为 Agent 有能力执行某个物理动作，就让能力本身成为行动正当性。

## 11. 建设顺序：由闭环深度，而不是由技术炫目程度决定

一个合理的长期 progression 可以是：

### Phase A — Instrumented Workstation

让当前计算机和少量硬件成为高可观察对象。

目标：跨 OS / firmware / telemetry / external measurement 形成可重放诊断闭环。

### Phase B — General Instrument Harness

把现成仪器、sensor nodes 与 embedded devices 接入 source-fenced semantic Tool surface。

目标：Agent 可以安全、可恢复地运行 measurement episode。

### Phase C — Automated Test Cell

加入 programmable power、environment control、robotic fixtures、camera 等。

目标：重复实验能够由 Runtime durable execution 承担。

### Phase D — Physical Artifact Loop

加入 electronics / PCB / rapid prototyping / mechanical fabrication。

目标：hypothesis → artifact → experiment → revision 可以在同一系统内循环。

### Phase E — Multi-agent Physical Environment

加入多个机器人、设备和 resource constraints。

目标：研究 adversarial adaptation、institution、authority、coordination 与 emergent strategy。

### Phase F — General Experimental Substrate

不同学科的 observation / actuation / experiment 可以通过 shared continuity、representation、authority、provenance 与 recovery machinery 被组合。

这些 phase 不是固定时间表，也不是必须全部完成。

每一阶段只有在前一阶段产生了真实 consumer pressure 和 consequence benefit 后，才值得继续扩张。

## 12. 安全与现实约束必须随着 physical reach 一起增长

软件中的错误可以很严重；物理系统的错误还会增加不可逆性、设备损坏和人身风险。

因此随着 Ordivon 获得 physical reach，必须同步提高：

```text
physical interlocks
emergency stop
bounded authority
safe-state defaults
experiment isolation
human consent where relevant
hazard classification
regulatory compliance
calibration discipline
provenance
reconciliation after uncertain effects
```

尤其需要拒绝：

```text
Autonomy
=>
Unlimited authority
```

以及：

```text
Successful command
=>
Safe physical outcome
```

进入化学、生物、高能、高压、高温、辐射等高风险实验领域时，专业实验制度、设施等级、法规和 Human authority 会成为独立的 load-bearing boundary；不能把电子/软件实验室的 autonomy model 直接平移过去。

## 13. 什么才说明这个 Horizon 真正在实现

不是拥有实验室空间。

不是设备数量。

不是“Agent 能控制机器人”。

更强的 success evidence 是，Ordivon 能完成越来越完整的链：

```text
1. 恢复一个真实未决问题
2. 识别当前 observation basis 的不足
3. 形成 rival hypotheses
4. 设计能区分 rival worlds 的实验
5. 获得正确 authority
6. 配置或制造需要的 instrument / artifact
7. 执行并保持 physical safety
8. 记录 measurement / effect / uncertainty / provenance
9. 区分 execution success 与 target consequence
10. 更新 Standing，允许 NO_CHANGE / rejection / reopening
11. 让未来 Agent 能恢复为什么这样判断
12. 让新的 standing 在适当时改变下一次默认环境
```

如果只能完成中间几个技术步骤，却不能形成这条 closed epistemic–physical loop，那么实验室仍然只是 Ordivon 外部的一组设备。

真正的目标是：

```text
Lab equipment
→
Ordivon capability
→
Persistent experimental intelligence
```

## 15. Reopen / demotion conditions

这个长期目标本身也必须可以被 Reality 改写。

至少以下情况应触发重新判断：

- commercial / shared laboratories 能以显著更低成本提供同等或更强 capability；
- physical experimentation 不再是当前重要问题的 bottleneck；
- safety / regulation / maintenance burden 超过实际 capability gain；
- 新型 remote instrumentation、simulation 或 digital twin 已经能提供足够 discriminability；
- Ordivon 的 owner architecture 变化，使某些 responsibility 应由外部系统承担；
- repeated experiments 证明某一层自建没有产生新的 reachable evidence/action space；
- laboratory growth 开始变成 infrastructure accumulation，而不是 problem-driven capability growth。

合法结果包括：

```text
CONTINUE
NARROW
OUTSOURCE
REPLACE CARRIER
DEMOTE
NO_CHANGE
```

因此这不是一个不可挑战的终局叙事。

## 16. 当前采用的长期表述

截至 2026-08-25，Ordivon 采用以下 Future Horizon：

> **Ordivon 的潜在边界不是 software。它的长期方向，是让有限智能能够跨数字与物理世界可靠地观察 Reality、改变 observation interface、产生新的 evidence、在正确 authority 下实施 intervention、测量 consequence，并把结果跨时间与 Agent replacement 累积为新的 capability。自己的实验室，是从“软件中的 Ordivon”走向“Reality 中的 Ordivon”的关键候选基础设施。**

同时保留一个约束：

> **不为了全栈而下沉。哪里真正阻碍 observation、discriminability、action、continuity、recovery 或 learning，就把能力延伸到哪里；成熟外部 carrier 足够时，就使用成熟外部 carrier。**

如果未来实验室最终成熟，它最值得追求的形态不是“一个装满设备的房间”，而是：

```text
Finite Intelligence
+
Persistent Knowledge
+
Compute
+
Sensors
+
Actuators
+
Experimental Infrastructure
+
Authority / Safety
+
Institutional Continuity
```

构成的一个可持续实验环境。

在那个环境中，Ordivon 不只是处理关于 Reality 的 information。

它能够向 Reality 提问，并让 Reality 回答。
