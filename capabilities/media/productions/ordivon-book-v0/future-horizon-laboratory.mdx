# Future Horizon — 从软件中的 Ordivon 到 Reality 中的实验智能

Status: `USER-ADOPTED LONG-TERM GOAL / NON-AUTHORITATIVE FUTURE HORIZON`

Adopted: `2026-08-25`

This document records a long-term direction chosen by the user. It is a **goal and design horizon**, not evidence that the described capabilities already exist, not a new semantic owner, and not an obligation to build every layer named below.

---

## 0. 为什么把它记录成 Future Horizon，而不是“第六章结论”

Ordivon Book 当前的责任是把已经存在的 standing、跨 owner synthesis、practice 与 consequence 编译成有限智能可消费的整体模型。

这份文本的 epistemic class 不同。

它记录的是一个已经明确选择的长期方向：

> **未来当 Ordivon 拥有自己的实验室后，让它从主要存在于软件中的 intelligence substrate，逐步扩展为能够直接观察、测量、实验、作用于物理 Reality，并把 consequence 重新纳入 cognition 的 experimental intelligence substrate。**

因此必须保留：

```text
Goal
!=
Current capability
!=
Prediction
!=
Guaranteed roadmap
```

这份 Horizon 的作用不是证明未来一定如此，而是让未来 Human / Agent 在做实验室、Workstation、Host、Runtime、Harness、World、Security、Media、Game、Interlocus 等决策时，知道存在这样一个长期方向，并能判断某个局部工程是否真正增加了通往它的 capability。

## 1. 核心目标：让 Ordivon 从信息消费者变成证据生产者

今天 Ordivon 的多数 Reality contact 仍然经过别人已经建立的数字接口：

```text
Internet
API
OS telemetry
market data
files
logs
web pages
external databases
third-party instruments / services
        ↓
     Ordivon
```

这使 Ordivon 可以做大量研究、判断、软件行动与数字世界中的闭环，但 Observation Interface 的很大一部分仍然由外部系统决定。

实验室真正重要的变化不是“多了硬件”，而是：

```text
Reality
  ↓
Ordivon chooses what to measure
  ↓
Measurement / experiment design
  ↓
Evidence
  ↓
Standing
  ↓
Physical intervention
  ↓
Consequence
  ↓
New measurement
  ↓
Revision
```

于是一个未知问题不再只能得到：

```text
search more information
reason harder
wait for external evidence
```

还可以得到：

```text
design a discriminating experiment
change the observation basis
build an instrument
intervene on Reality
produce new evidence
```

这是这一长期目标最重要的 capability transition：

```text
Information consumer
→
Evidence producer
```

以及：

```text
Software action
→
Reality intervention
```

## 2. Ordivon 的边界不再以 software 为天然终点

当前实现 substrate 仍然主要是 software。

但 owner 的 responsibility domain 不需要与实现层重合。

未来实验室允许 Ordivon 沿以下层次扩展：

```text
Human / Agent
      │
      ▼
Ordivon cognition / coordination
      │
      ▼
Application / software
      │
      ▼
Operating systems / services / drivers
      │
      ▼
Firmware / BIOS / UEFI / EC / BMC
      │
      ▼
Embedded electronics / MCU / FPGA / PCB
      │
      ▼
Sensors / instruments / buses / power
      │
      ▼
Robotics / actuators / mechanisms
      │
      ▼
Fabrication / automated test / physical experiment
      │
      ▼
Reality
```

但这不是一条要求逐层“占领”的 roadmap。

真正的扩展原则是：

> **只有当某一层阻止有限智能获得重要的 observation、discriminability、action、recovery、authority、continuity 或 consequence feedback 时，才由 capability pressure 驱动向该层深入。**

因此：

```text
Lower-level
!=
More important

Own more layers
!=
More capable

Self-built
!=
Better
```

如果成熟外部设备、标准、OS、BMC、机器人平台或实验仪器已经提供了足够好的 capability，Ordivon 应优先消费它们，而不是为了“全栈”复制已有工业体系。

## 3. 第一条扩展轴：Machine Reality

距离当前 Ordivon 最近的实验室扩展，是把“计算机本身”从一个大致由 OS/API 表示的对象，变成可以跨软件—固件—电气层联合观察的 Reality。

今天一个黑屏、死机、功耗异常或 sleep/wake failure 往往只能通过：

```text
Windows event
GPU / chipset driver state
ACPI exposure
BIOS version
software telemetry
behavioral reproduction
```

来推断。

实验室化以后，可能加入：

```text
power rail measurement
thermal imaging
logic / bus observation
panel / display signal observation
EC / firmware trace
external watchdog
independent timestamped telemetry
```

然后把多个 locus 时间对齐：

```text
OS event
GPU state
EC state
power transition
physical display consequence
```

这会把很多“软件猜测”转化为更强的 causal discrimination。

长期目标不是让 Workstation 变成一个 BIOS 工程项目，而是让它能够在必要时跨层回答：

> **这台机器的真实状态是什么？哪个 layer 的 transition 导致了当前 consequence？**

## 4. 第二条扩展轴：自己制造 Reality Interface

当现有 instrument 或 API 无法提供需要的 measurement basis 时，Ordivon 应能够逐步设计自己的观测与控制节点。

可能的 substrate 包括：

```text
MCU
FPGA
ADC / DAC
I²C / SPI / UART / CAN / USB / Ethernet
custom sensors
power measurement
synchronization / timestamping
firmware
PCB
```

例如一个实验需要同时观测：

```text
16-point temperature
current / voltage
vibration
fan / motor state
software events
```

Ordivon 不必被一个现成产品的 schema 限制，而可以形成一个 task-specific instrument。

这使 Harness 的长期含义可以从：

```text
Tool Harness
```

扩展到：

```text
Reality Instrument Harness
```

即 Human / Agent 面对的不是寄存器、串口命令和供应商 SDK，而是 source-fenced 的 semantic operations，例如：

```text
observe_temperature()
observe_power()
calibrate()
set_sample_rate()
run_experiment()
```

底层仍可由不同仪器、firmware 与 protocol 实现。

## 5. 第三条扩展轴：Physical Host / Out-of-band Continuity

Host 今天主要承担 semantic continuity：让 Agent replacement、context loss、时间跨越之后仍能恢复工作状态，而不伪造 current truth。

实验室提供一个重要的新压力：

> 如果主 OS、Agent process、network 或 compute node 本身失效，continuity 谁来承担？

未来可能出现一个独立于主计算路径的 physical host controller / management plane，负责：

```text
power state
watchdog
out-of-band telemetry
reboot / recovery
crash-adjacent physical logs
UPS / battery
thermal emergency handling
instrument safe-state
```

这不意味着 Host 必须自己实现一个 BMC。

更稳定的目标是：

```text
Agent continuity
+
Compute continuity
+
Physical experiment continuity
```

在主 cognition substrate 消失时，仍保留足够事实，使未来 Agent 可以知道：

- 发生了什么；
- 哪些状态仍有效；
- 哪些状态只是历史；
- 哪些实验需要安全终止；
- 哪些 action 已经产生物理 effect；
- 哪些 effect 仍然 unknown。

## 6. 第四条扩展轴：Robotic Action / Embodiment

机器人、运动平台、自动夹具和执行器会改变 Ordivon Action 的基本形态。

今天常见 action 是：

```text
write file
call API
execute process
send request
submit order
```

未来可以包括：

```text
move
pick
place
connect
press
rotate
align
inspect
assemble
replace
measure
repeat
```

于是：

```text
Intent
→
Authorized physical action
→
Physical effect
→
Observed consequence
```

成为 Ordivon 的一等问题。

这会给 Runtime、Security、Normative、World 与 Interlocus 带来比纯软件环境更强的 Reality pressure，因为物理 action：

- 往往不可完全回滚；
- 有惯性和延迟；
- 可能伤害设备、人或环境；
- observer 与 actuator 可能失配；
- execution success 不等于 desired effect；
- physical state 可能在数字系统之外继续演化。

因此 physical embodiment 必须比普通 API automation 更严格地区分：

```text
Capability
!=
Authority
!=
Commitment
!=
Execution
!=
Effect
!=
Consequence
```

当 measurement、instrument control、robotic action、artifact capture 与 continuity 足够成熟后，Runtime 可以承载的不再只是 computation Job，而是一个完整的 Experiment episode。

例如：

```text

→ recover prior hypotheses / failures

World
→ establish current board / firmware / instrument state

SCD
→ structure rival hypotheses

PPD / Research
→ find discriminating pressure

→ admit experiment

Harness
→ control chamber / PSU / scope / JTAG / sensors

Physical experiment
→ produce traces / video / telemetry / failure

Interlocus
→ bind physical board ↔ firmware ↔ trace ↔ experiment

Security
→ validate measurement / identity / provenance

Standing revision
→ retain / reject / narrow / reopen
```

这里 Runtime 的 durable object 可以逐渐出现 physical-experiment semantics：

```text
setup
calibration
inputs
execution
measurements
artifacts
anomalies
cleanup
provenance
recovery
```

但只有在真实 repeated pressure 出现后，才应该把这些抽象提升为 Runtime 核心结构。

## 8. 第六条扩展轴：Fabrication / Physical Artifact Creation

实验室还可能把 Representation → Artifact 的链缩短。

可能包括：

```text
CAD → 3D print
schematic → PCB
mechanical design → CNC / laser / machining
firmware → embedded device
robotic fixture → automated assembly / testing
```

真正重要的指标不是“我们拥有多少制造设备”，而是：

> **一个 hypothesis 所需要的新 physical artifact，能否在足够低的 transaction cost 下进入同一个 cognition–experiment–revision loop？**

这会改变 Computational Possibility / Search Geometry：

过去因为制造成本过高而不可达的实验分支，可能变成当天就能验证的 hypothesis。

因此 fabrication capability 本身会改变 reachable problem space。

## 9. 各 owner 在这个 Horizon 中可能发生什么变化

这份 Horizon 不预先重写 owner 边界，但可以记录未来 pressure 可能把哪些 responsibility 推向新的形态。

### World

从主要消费外部数字 Reality，扩展到管理：

```text
sensor state
calibration state
physical state estimation
measurement uncertainty
observer identity
cross-sensor consistency
```

World 的关键问题会变成：

> 当前可行动的 physical Now 是什么？

### SCD

从 representation / structural distinction 研究，进一步面对：

```text
raw signal → feature → causal variable
multi-modal alignment
measurement basis selection
experimental representation
```

Representation 不再只是信息表达；它可以直接决定哪些物理机制可被看见。

### Harness

从 Tool / Agent capability interface 扩展为：

```text
Agent ↔ instrument
Agent ↔ robot
Agent ↔ embedded device
Agent ↔ experiment
```

但仍应保留 source truth 与 authority conservation，而不是让一个 convenient semantic Tool 自动获得物理行动权。

### Runtime

从 computation / Workspace / Job / Attempt / Artifact，向可恢复的 experiment execution substrate 延伸。

重要的新 distinction 会包括：

```text
command delivered
!=
actuator moved
!=
physical effect occurred
!=
target consequence achieved
```

### Host

从 semantic continuity 延伸到 physical system continuity 与 out-of-band recovery。

### Interlocus

会获得一个非常具体的新任务：把数字 lineage 与实体物体绑定。

例如：


### Security

从 cybersecurity 向 `Reality integrity` 扩展。

```text

which ADC

which timestamp

```

因此长期 Security pressure 是：


### Atlas


同一个实验的：

```text

software trace

```

因此：

```text

```

### Game

Game 可以从 synthetic world transition authority 延伸到 synthetic–physical environments：多机器人、多 Agent、真实资源、真实传感器、真实 failure。

这会让 Game × Security × Normative 的 institution / adversary / incentive 研究获得真实 consequence。

### Normative

Physical autonomy 会迫使 Normative 更明确地区分：

```text

safety constraint
institutional authority
physical capability

```

尤其不能因为 Agent 有能力执行某个物理动作，就让能力本身成为行动正当性。

## 11. 建设顺序：由闭环深度，而不是由技术炫目程度决定

一个合理的长期 progression 可以是：

### Phase A — Instrumented Workstation

让当前计算机和少量硬件成为高可观察对象。

目标：跨 OS / firmware / telemetry / external measurement 形成可重放诊断闭环。

### Phase B — General Instrument Harness

把现成仪器、sensor nodes 与 embedded devices 接入 source-fenced semantic Tool surface。

目标：Agent 可以安全、可恢复地运行 measurement episode。

### Phase C — Automated Test Cell

加入 programmable power、environment control、robotic fixtures、camera 等。

目标：重复实验能够由 Runtime durable execution 承担。

### Phase D — Physical Artifact Loop

加入 electronics / PCB / rapid prototyping / mechanical fabrication。

目标：hypothesis → artifact → experiment → revision 可以在同一系统内循环。

### Phase E — Multi-agent Physical Environment

加入多个机器人、设备和 resource constraints。

目标：研究 adversarial adaptation、institution、authority、coordination 与 emergent strategy。

### Phase F — General Experimental Substrate

不同学科的 observation / actuation / experiment 可以通过 shared continuity、representation、authority、provenance 与 recovery machinery 被组合。

这些 phase 不是固定时间表，也不是必须全部完成。

每一阶段只有在前一阶段产生了真实 consumer pressure 和 consequence benefit 后，才值得继续扩张。

## 12. 安全与现实约束必须随着 physical reach 一起增长

软件中的错误可以很严重；物理系统的错误还会增加不可逆性、设备损坏和人身风险。

因此随着 Ordivon 获得 physical reach，必须同步提高：

```text
physical interlocks
emergency stop
bounded authority
safe-state defaults
experiment isolation
human consent where relevant
hazard classification
regulatory compliance
calibration discipline
provenance
reconciliation after uncertain effects
```

尤其需要拒绝：

```text
Autonomy
=>
Unlimited authority
```

以及：

```text
Successful command
=>
Safe physical outcome
```

进入化学、生物、高能、高压、高温、辐射等高风险实验领域时，专业实验制度、设施等级、法规和 Human authority 会成为独立的 load-bearing boundary；不能把电子/软件实验室的 autonomy model 直接平移过去。

## 13. 什么才说明这个 Horizon 真正在实现

不是拥有实验室空间。

不是设备数量。

不是“Agent 能控制机器人”。

更强的 success evidence 是，Ordivon 能完成越来越完整的链：

```text
1. 恢复一个真实未决问题
2. 识别当前 observation basis 的不足
3. 形成 rival hypotheses
4. 设计能区分 rival worlds 的实验
5. 获得正确 authority
6. 配置或制造需要的 instrument / artifact
7. 执行并保持 physical safety
8. 记录 measurement / effect / uncertainty / provenance
9. 区分 execution success 与 target consequence
10. 更新 Standing，允许 NO_CHANGE / rejection / reopening
11. 让未来 Agent 能恢复为什么这样判断
12. 让新的 standing 在适当时改变下一次默认环境
```

如果只能完成中间几个技术步骤，却不能形成这条 closed epistemic–physical loop，那么实验室仍然只是 Ordivon 外部的一组设备。

真正的目标是：

```text
Lab equipment
→
Ordivon capability
→
Persistent experimental intelligence
```

## 15. Reopen / demotion conditions

这个长期目标本身也必须可以被 Reality 改写。

至少以下情况应触发重新判断：

- commercial / shared laboratories 能以显著更低成本提供同等或更强 capability；
- physical experimentation 不再是当前重要问题的 bottleneck；
- safety / regulation / maintenance burden 超过实际 capability gain；
- 新型 remote instrumentation、simulation 或 digital twin 已经能提供足够 discriminability；
- Ordivon 的 owner architecture 变化，使某些 responsibility 应由外部系统承担；
- repeated experiments 证明某一层自建没有产生新的 reachable evidence/action space；
- laboratory growth 开始变成 infrastructure accumulation，而不是 problem-driven capability growth。

合法结果包括：

```text
CONTINUE
NARROW
OUTSOURCE
REPLACE CARRIER
DEMOTE
NO_CHANGE
```

因此这不是一个不可挑战的终局叙事。

## 17. 2026-08-25 PPD 收口修正：实验室资本不等于设备库存

在记录这个 Horizon 之后，Computing 又对“有限智能是否能主动建设环境来扩大未来能力”做了一轮独立 PPD / destructive-subtraction 研究。完整 closeout 由 `ordivon-computing@d6017c19da90ac63f6fd95ddd07f464a61a37119` 的 `research/CONSTRUCTIVE-CAPABILITY-ENVIRONMENT-CLOSEOUT-20260825.md` 承载。

这轮研究没有创建新的 Environment / Lab owner，反而进一步收紧了本 Horizon。

### 17.1 环境变化本身不是 capability 证据

未来不能因为：

```text
买了仪器
接了 API
增加了机器人
增加了传感器
增加了可调用动作
```

就宣布 Ordivon 获得了新 capability。

必须继续区分：

```text
EnvironmentChange
!=
CapabilityChange

LatentAffordance
!=
RealizedCapability

FrontierExpansion
!=
InfrastructureCapital
```

一个 capability 至少还要经过当前 consumer 的发现、选择、admission、execution 与 target-relative consequence 才能被实际消费。

### 17.2 更少的局部自由，有时反而保存更多未来能力

Game 的一个确定性 deletion probe 给出了很小但很干净的反例：Primitive World 允许 Security 拿走唯一 sealant，但 Security 没有 `seal_hull`，当前 World 又没有 transfer/release。一旦绕过 Team constraint 让它拿走 sealant，Engineer 之后再也拿不到该资源，当前任何持有者都无法封堵 hull。

因此 Team Context 删除这个 primitive-legal action 时：

```text
local raw action freedom ↓
future valid joint reachability ↑
```

这并不证明新的 institution theory；经典 safe-state / deadlock-avoidance 已经覆盖一般机制。对 Future Lab 真正重要的是：

> **interlock、resource reservation、authority gate、safety constraint 不一定只是限制能力；当它们保护了明确的未来可达性、安全性或合法性不变量时，它们本身可以成为 capability-enabling environment。**

所以：

```text
MoreRawActions
!=
MoreValidCapability
```

### 17.3 Continuity 的修正：不要把“persistent substrate”神化

Atlas × Host × Harness 的独立 successor 研究最终加入了强 generic control：indexed retrieval + generic typed policy compiler 在三轮 H=256 ratchet 中达到 33/33，复现了此前 operation-compiled successor representation 的优势。

因此：

```text
storage
indexing
materialized current view
policy compilation
```

都不能被写成 Ordivon 独有的 persistent-intelligence substrate。

真正留下的窄原则是：

> **responsibility-preserving reactivation：Agent replacement 后，只从当前 operation 的 load-bearing owners 重新恢复那些会改变下一步行动的 premises；保留 history 但不把 history 提升成 current authority；显式保留 unresolved effect / obligation；然后重新编译 affordance。**

这意味着未来 physical experiment continuity 也不应该维护一个巨大的永久 `PhysicalState`。更重要的是能够重新获得当前实验真正需要的：

```text
specimen identity
configuration
calibration / uncertainty
physical binding
unresolved effect
safety state
owner-qualified current evidence
```

### 17.4 最重要的新资本模型：Instance、Reconfiguration、Reconstruction 分开

过去 Workstation 的 `isolated-equipment` 给出了一个自然的内部正例。早期 Security 的 Nmap / TShark / mitmproxy isolated roots 后来都自然 expired；它们没有因为“曾经有用”而永久 active。

但同一个 environment-construction mechanism 后来被独立 Game workload 再次消费，用来建立 Tiled、Inkscape、RenderDoc 与 Blender ABI 环境；Blender 还自然推动该 mechanism 在不放松 signature / TTL / isolation 的前提下扩大 package-closure capacity。

因此更成熟的基础设施资本表示是：

```text
CapabilityInstance
!=
CapabilityProduction / ReconfigurationMechanism
!=
ReconstructibleDesignOption
```

三者都可能有价值，但 currentness、维护成本与证据等级不同。

一个具体 instrument setup 可以退役，同时更高层的 capability 仍由：

```text
reproducible configuration
fixture design
calibration procedure
source / provenance
control adapter
fabrication route
safe reconstruction path
```

保留下来。

因此 Future Lab 的建设原则进一步修正为：

> **尽量保留“可靠地再次形成正确实验环境”的能力，而不是默认永久维持每一个曾经有用的实验环境。**

### 17.5 Capability currentness 是 target-relative 的

未来不能维护：

```text
oscilloscope = available
robot = available
sensor = calibrated
```

然后把它们当永久 capability truth。

更合理的是：

```text
AssetExists
!=
CurrentCapability(target, time)
```

对于一个具体 target，current capability 可能依赖：

```text
physical condition
calibration / uncertainty
probe / fixture identity
firmware / software compatibility
current supply / service availability
authority
interlock / safety
provenance / binding
supporting environment
consumer discoverability
```

所以本 Horizon 不授权一个全局 Capability Registry。物理 currentness 仍应由当前 operation 的 load-bearing owners 提供。

### 17.6 因而 Future Lab 更像“可重构证据生产基础设施”

这轮研究之后，最值得追求的长期形态进一步从：

```text
a room containing many instruments
```

转向：

```text
Reality pressure
→ identify missing discriminability / action
→ strongest mature external carrier first
→ configure the smallest trustworthy environment
→ experiment / intervention
→ evidence / consequence
→ retain standing + provenance
→ retire / reconfigure / reconstruct as needed
```

更持久的 Lab capital 可能集中在：

```text
standard interfaces
reusable fixtures
calibration / provenance procedures
synchronized acquisition
programmable environment / power
physical-digital identity binding
safe interlocks
robotic / fabrication setup capability
recoverable experiment protocols
```

而不是设备数量。

这不会削弱“Information Consumer → Evidence Producer”的长期目标；它只是给这个目标增加了一个更成熟的约束：

> **Ordivon 最终应该擅长的，不是拥有所有环境，而是在 Reality 真正提出压力时，形成最小、可信、当前、可恢复的实验环境，然后让 Reality 给出新的 evidence。**

## 18. 2026-08-26 世界模型修正：文明已经实现，不等于我们已经拥有；但也不应先判为不可达

继续展开实验室 Capability Atlas 时，一个比“软件是否应该向硬件下沉”更一般的问题浮现出来。

过去很容易把下面几件事混在一起：

```text
我们没有内部实现
我们没有对应设备
我们没有这个专业 owner
我们没有亲自做过
我们当前做不到
这件事原则上不可达
```

这些不是同一个 standing。

尤其当人类文明已经稳定实现某个 target 时，`当前 Ordivon 没有内部实现` 对于“原则上是否存在一条 Reality path”其实是很弱的负证据。

### 18.1 新的默认先验不是“都能做”，而是“先不要关闭”

本 Horizon 现在增加一个更精确的 search prior：

```text
Human-civilization-realized capability
→ CandidateReachable
```

它明确不等于：

```text
Human-civilization-realized capability
→ CurrentOrdivonCapability
```

因此：

```text
NotOwned
!=
NotReachable

NotLocal
!=
NotReachable

NotInCurrentOwner
!=
OutsideOrdivonProblemSpace
```

但同时：

```text
SupplierExists
!=
CurrentCapability

HumanRealized
!=
CurrentOrdivonCapability
```

这不是乐观主义声明，而是一条**防止有限智能过早收缩搜索空间**的规则。

当某个 target 已经被人类、企业、实验室、工业系统或公共基础设施稳定实现时，更成熟的第一反应不是：

> “我们没有这个领域，所以不做。”

而是：

> **“哪一条 causal path 能把这个已经被文明实现的 capability，转换成当前 target 下可调用、可授权、可验证的能力？”**

### 18.2 Ordivon 的 capability boundary 不应等于 implementation boundary

人类文明已经形成了一个巨大的 capability ecology：

```text
people
experts
firms
markets
standards
logistics
machines
manufacturing networks
shared facilities
remote laboratories
software
institutions
```

一个 target 的实际路径可以自然穿过多个不同 carrier：

```text
Ordivon design
→ contract PCB assembly
→ vendor surface treatment
→ local fixture
→ shared metrology
→ software analysis
→ new Standing
```

其中某一步没有被 Ordivon 自己实现，并不会自动让整条 path 失去 capability 意义。

因此未来应继续区分：

```text
OwnerBoundary
!=
CarrierBoundary
!=
ReachabilityBoundary
```

这与本 Horizon 原有的：

```text
Self-built != Better
```

一致，但更强。

原来的原则主要回答：

> 已知需要某个 capability 时，是否应该自己造？

新的原则更早一步回答：

> **我们是否因为它“不在自己这里”，就在问题形成阶段把它删掉了？**

### 18.3 “做不到”必须被拆成具体 blocker

以后一个 target 不能只被标记成模糊的 `cannot do`。

至少要问它究竟被什么挡住。

可能是真正的 hard boundary：

```text
logical contradiction
physical impossibility under the relevant regime
causal / information destruction
fundamental computability / decidability limit
```

也可能只是当前有限系统的 contingent / effective blocker：

```text
knowledge / method
compute / search / time
capital
instrument / facility
material / supply
logistics / lead time
precision / metrology
interface / integration
authority / consent
safety
law / regulation
transaction / coordination
provenance / verification
```

这一区分很重要，因为：

```text
PhysicallyPossible
!=
EpistemicallyRecoverableNow
```

同时：

```text
PhysicallyReachable
!=
AuthorizedReachable
!=
SafeAdmissibleReachable
```

一个已经被别人做过的目标，可以排除一部分“绝对不可能”解释，却不能自动消除预算、地点、制度、信息、精度和安全约束。

### 18.4 Candidate reachability、路径成立与当前 capability 必须分开

新的 Horizon 使用三个层次：

```text
CandidateReachable
!=
PathQualified
!=
RealizedCurrentCapability
```

**CandidateReachable**：已有足够理由认为值得寻找路径。文明已有实现是很强的正证据。

**PathQualified**：已经找到具体 carrier chain，并对 access、成本、currentness、authority、安全、接口与验证要求有足够边界，可以认真规划执行。

**RealizedCurrentCapability**：当前 consumer 真能发现、admit、execute 这条 path，并获得 target-valid consequence / evidence。

这延续了此前已经建立的：

```text
LatentAffordance != RealizedCapability
```

所以新认知不会反过来制造 capability inflation。

### 18.5 “文明 API”只能是比喻，不是新架构

按需制造、共享实验设施、Cloud Lab、专家服务和成熟供应链确实让越来越多过去必须自建的能力变成可调用 carrier。

但不能因此创建：

```text
Civilization API
Global Capability Graph
Reachability Registry
Universal Provider Contract
```

文明中的 carrier 具有完全不同的：

```text
authority
currentness
latency
cost
quality
interface
reliability
verification
failure semantics
```

所以真正值得保留的是：

> **把文明视为 capability search space，而不是统一 capability platform。**

### 18.6 Reachability 会递归扩张，但不保证单调增长

一个新 capability 可以成为另一个 capability 的 carrier。

例如：

```text
MCU control
→ custom sensing
→ new physical evidence
→ better experiment design
→ custom fixture
→ new measurement geometry
→ previously hidden mechanism becomes discriminable
```

因此 capability acquisition 可能改变未来的 reachability graph。

这也是为什么实验室的价值可能具有复利性质。

但不能写成：

```text
more equipment
=>
monotonically more capability
```

新设备也会增加：

```text
maintenance
calibration
complexity
attack surface
safety burden
attention cost
```

而一个 constraint 甚至可能通过删除局部 action，保存更多未来 valid reachability。

因此更窄的 standing 是：

> **Capability 可以通过新 carrier 与新组合递归地打开后续路径；是否形成净能力增长仍然由 target-relative consequence 判断。**

### 18.7 这重新定义了自己的实验室为什么重要

自己的实验室不再是：

> “Ordivon 能接触物理 Reality 的地方。”

因为大量物理能力本来就可以通过外部 carrier 获得。

它更像是一个：

```text
Reachability Amplifier
```

尤其在以下关系上有价值：

```text
feedback latency
iteration cadence
local physical identity
currentness
independent observation
troubleshooting / re-entry
automation
safe interlock
provenance
reconfiguration
uncertain-effect recovery
```

所以实验室最应该内部拥有的，不是“所有技术门类”，而是那些：

- 高频；
- 低 latency 极其重要；
- 需要反复修改；
- external handoff 会破坏 provenance / currentness / recovery；
- 能成为大量后续 capability 的通用 carrier；
- ownership 明显改善 target-relative consequence；

的能力。

而稀疏、昂贵、专业维护重、设施要求高、监管复杂、独立外部测量反而更有证据价值的过程，可以长期保持 external/shared/contract-first。

### 18.8 因此 Future Lab 的总体扩展法再次修正

原来的：

```text
important capability pressure
→ blocking Reality relation
→ strongest mature external carrier first
→ residual local construction
```

现在在最前面再加一步：

```text
important target
→ do not close by domain / ownership boundary
→ ask whether civilization already realizes an equivalent target
→ search source-neutral carrier paths
→ classify actual blocker
→ choose strongest admissible path
→ construct only residual relation
→ verify consequence
→ preserve the cheapest trustworthy route back
```

这意味着未来 Ordivon 面对 chemistry、materials、mechanics、optics、biology、manufacturing 或任何陌生领域时，不应该因为当前项目 topology 没有对应 owner 就预先缩小问题。

领域只是知识与实践的历史组织方式。

真正的 stopping condition 应该是：

```text
在当前 target / resource / authority / evidence boundary 下，
没有一条 admissible path 能跨过已经识别的 blocker
```

或者相反：

```text
一个成熟外部 carrier 已经足够好，
所以没有任何本地 construction residual 值得拥有
```

二者都是成熟结果。

### 18.9 当前采用的更强长期表述

因此，截至 2026-08-26，本 Horizon 对 Ordivon 潜在能力边界的表述进一步修正为：

> **Ordivon 的能力边界不应由当前软件仓库、项目 owner、已有设备或自己直接执行的工艺来定义。凡是人类文明已经可靠实现的 target，应首先保留在 candidate reachability search space 中，然后寻找由内部与外部 carrier 组成的具体 causal path，并用 currentness、resource、authority、safety、precision 与 evidence 约束它。只有在具体 blocker 被识别以后，才有资格说当前不可达；只有当路径真正被当前 consumer 可靠实现以后，才有资格说 Ordivon 已经拥有该 capability。**

这个 standing 不承诺：

> “人类能做到的，Ordivon 最终都一定能做到。”

它只拒绝一种更早、更隐蔽的失败：

> **在 Reality 还没有真正阻止我们之前，先因为自己的组织边界、知识边界或资产边界，把可能的路径从世界模型里删掉。**

这使未来实验室的意义更加清楚。

它不是把 Ordivon 从 software 变成一个封闭的 full-stack physical organization。

它是让有限智能越来越擅长：

```text
发现可达路径
调用文明已有能力
构造缺失 residual
验证真实 consequence
再把新 capability 变成下一轮 reachability 的 carrier
```

从这个角度看，自己的实验室只是更大 capability ecology 中一个高带宽、低延迟、可重构、可验证的本地节点。


### 18.10 Reality authority 不等于 Research passivity

对 Historical Reachability 的继续实验暴露了另一个相反方向的错误。

为了避免“自己生成的 evidence 取代 Reality”，有限智能很容易滑向：

```text
只有自然发生的事件才是真实例
只有 owner-native episode 才值得作为强 evidence
没有自然 pressure 就先等待
```

这同样过强。

更成熟的关系是：

```text
RealityAuthority
!=
ResearchPassivity
```

以及：

```text
NaturalPressure
!=
OnlyAdmissiblePressure

DesignedPressure
!=
ManufacturedTruth
```

实验、measurement、countermodel、simulation、synthetic world、formal construction、历史轨迹和外部成熟研究都可以主动制造 **discriminating pressure**。

它们不能自动制造 current Reality truth；但它们完全可以改变：

```text
which hypotheses remain live
which assumptions are exposed
which paths are worth testing
which counterexamples exist
which observation would discriminate
```

因此 Future Lab 不应该被理解成一个等待 Reality 自己产生足够好案例的场所。

它应该逐渐成为：

> **有限智能主动构造高判别实验条件、同时让 Reality 保留最终 claim authority 的环境。**

### 18.11 Evidence 应该形成 ecology，而不是“自然事件”单一等级

不同 evidence regime 适合回答不同问题：

```text
field / owner-native Reality
→ current state / actual consequence / current authority

controlled intervention
→ causal discrimination / deletion / substitution

synthetic world / simulation
→ mechanism / edge case / counterfactual possibility

formal construction
→ implication / impossibility / counterexample under explicit premises

source-locked history
→ prerequisite / path dependence / dormancy / diffusion / bottleneck migration

external mature research / industry
→ already-solved mechanism and current carrier space
```

它们的价值不能用一个简单强弱排名代替。

真正必须保存的是各自的 **claim ceiling**：

```text
SyntheticMechanismEvidence
!=
CurrentWorldFact

ModelPossibility
!=
PhysicalValidity

HistoricalTrajectoryEvidence
!=
CurrentCapability

FieldConsequence
!=
UniversalLaw
```

所以 Future Lab 的研究纪律不应该是：

> “只相信自然发生。”

而应该是：

> **当前 uncertainty 需要哪一种 pressure 才能最好地区分 live alternatives？这类 evidence 最多允许我们说到哪里？**

### 18.12 History 的价值不是复述过去，而是恢复 capability transition

Computing 已完成的 1760–2026 历史 programme 包含 320 条 innovation / discovery trajectories 与 96 个 Deep Anchors。

这批历史 evidence 最有价值的对象并不是：

```text
who invented what
final historical outcome
famous success story
```

而是：

```text
before blocker
→ what materially changed
→ what path / question became open or closed
→ what boundary still remained
```

新的实验还给了一个重要的 representation 修正。

把历史强行编码为一套固定 transition taxonomy 时，跨 replicate 的 label agreement 很低；而删除 taxonomy，只保留：

```text
BeforeBlocker
BasisChange
PathDelta
RemainingBoundary
EvidenceCeiling
```

两个独立抽取在选定的十个跨时代 case 上稳定恢复了相同 causal delta，随后两个不同模型层的 pair adjudication 都得到五个字段 10/10 semantic equivalence、0 material contradiction。

所以本 Horizon **不采用**一个全局 Historical Transition ontology。

更窄、更可靠的长期表示是：

> **当 history 对当前 reachability 有价值时，恢复最小 causal delta，而不是把历史塞进固定类别。**

这也意味着：

```text
ProcessMemory
!=
RawTranscript

TerminalResultValue
!=
TransitionValue
```

有些失败、dormant route、instrument change、standard、constraint 或 reconstruction lineage 值得保存，不是因为“过程天然珍贵”，而是因为删除它会让未来 consumer 更难重新发现 blocker、reopen condition 或 capability path。

### 18.13 历史上的 load-bearing step，今天未必需要自己重走

Historical Reachability 与 Civilization-Mediated Reachability 合起来以后，还出现一个很重要的修正：

```text
HistoricalImportance
!=
LocalOwnershipPressure
```

一个 instrument、machine tool、manufacturing process 或 laboratory procedure 在历史上可能是决定性的 prerequisite。

但今天它可能已经被成熟 carrier 吸收为：

```text
remote lab
contract measurement
on-demand manufacturing
PCB assembly service
shared facility
expert / institutional service
```

于是：

```text
Historical construction burden
can migrate into
carrier qualification burden
```

当前 consumer 不再需要复制整条历史建设链，却仍然必须负责：

```text
target-relative specification
sample / artifact identity
method fitness
currentness / provenance
authority / safety
interface / integration
verification
latency / re-entry requirements
```

因此 history 还可以被用作一种 **substitution map**：

```text
HistoricalStep
→ ask whether civilization now supplies it
→ inherit when target semantics survive
→ construct only the residual
```

这进一步解释了为什么 Future Lab 不应该追求重建整个人类工业体系。

自己的实验室最有价值的地方，是那些 externalization 会显著破坏：

```text
feedback latency
iteration cadence
physical identity / currentness
custom experiment freedom
independent evidence
re-entry / troubleshooting
safe interlock
provenance
reconfiguration
```

的关系。

其余能力可以继续由文明中的成熟 carrier 承担。

### 18.14 修正后的更完整长期循环

因此这一阶段之后，Future Lab 的研究—构造循环可以压缩为：

```text
important target / uncertainty
→ reject premature domain / ownership closure
→ search current civilization carriers
→ recover relevant historical causal transitions
→ generate alternative basis changes / countermodels
→ choose the cheapest strong discriminating evidence regime
→ preserve its claim ceiling
→ configure / acquire / construct only the residual environment
→ intervene / observe
→ verify consequence against Reality
→ retain minimal result + transition lineage when deletion would matter
→ revise future reachability
```

最重要的新增关系是：

> **Ordivon 不需要等待世界碰巧制造足够好的 falsifier。它可以主动构造让自己的 world model 暴露错误的 pressure；但它不能因为 pressure 是自己设计的，就把实验结果提升到证据没有支持的 standing。**

这让 Future Lab 的“Evidence Producer”含义更加完整：

不是制造答案，

而是制造更好的问题条件，让 Reality、history、formal model、simulation 与 experiment 各自在正确边界内回答它们真正能够回答的问题。
