# Reliable execution is a different problem

AI systems can propose code and commands. That does not make the resulting execution durable, observable, or safe to repeat after an uncertain response.

Ordivon Runtime addresses that physical execution boundary. It binds work to an exact Git Workspace, commits a durable Job identity, supervises the resulting process tree, preserves bounded evidence, and exposes explicit observation and recovery.

<RuntimeFlow activeStage="evidence" />

The first production will pair this explanation with one real end-to-end proof:

```text
workspace.open
→ workspace.read / workspace.patch
→ workspace.execPlan
→ exact request replay / task.list
→ task.observe
→ artifact.read
→ workspace.diff
→ workspace.get
→ workspace.close(expectedSourceStateDigest)
```

The point is not that every effect becomes idempotent. The point is that an admitted operation has a stable request identity and recorded Job, so uncertain delivery does not require blind redispatch. The resulting evidence and source changes remain inspectable, and cleanup can be fenced to the exact Workspace state that was reviewed.

The film will state the boundary directly: Runtime is operational for owner-trusted Linux environments. It does not decide semantic Task completion and is not a hostile multi-tenant sandbox.
