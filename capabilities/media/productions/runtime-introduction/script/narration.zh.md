# 中文旁白草稿

Agent 会写代码，不代表它能够可靠地执行代码。

一次命令可能持续得比当前对话更久，也可能丢失响应、遗留子进程，或者留下无法立即判断的结果。

Ordivon Runtime 是面向 Agent 与自动化工作流的本地持久执行层。

这次演示从一个确切的源码版本开始。受保护的 Patch 只修改已经读取和校验过的文件状态，随后一个稳定的请求身份提交持久 Job，并建立由 Runtime 管理的 Attempt。

客户端可以观察真实的步骤进度和有界输出。重新连接并重放同一个操作请求时，Runtime 返回同一个已记录的 Job，而不是静默派发一份新工作。

Job 保存 Artifact 与终端证据，将执行绑定到对应的 Workspace、源码版本和 Attempt；源码影响仍然以结构化 Diff 可见。

审查完成后，客户端读取完整的源码状态摘要，并且只关闭这个已经确认过的精确状态。

Runtime 并不声称所有外部效果都天然幂等。它保存物理执行的身份、进程归属和证据，使不确定状态能够被观察和主动恢复。

Runtime 面向所有者信任的 Linux 环境。它不是敌对代码沙箱，也不负责判断用户的语义目标是否完成。
