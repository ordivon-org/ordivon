# Ordivon Media

Ordivon Media is an **optional domain owner for intentional media mediation and authored expression**. Ordinary observer-facing projections remain with their natural source/client owners unless a task explicitly activates Media semantics.

Media does **not** own the underlying domain truth being mediated.

## Constitution v0

1. **Activated media mediation.** Media owns media-specific projection/composition/transformation semantics only after a task selects Media; it does not own every representation or UI projection in Ordivon.
2. **Source-truth conservation.** A Media projection never supersedes, strengthens or silently currentizes source-owner truth.
3. **Studio retained.** Ordivon Studio remains Media's authoring, production, editing, composition, transformation, rendering and packaging capability plane.
4. **Web/client autonomy.** Web and other clients own their ordinary interface projections. They consume Media only when a concrete authored/media contract is selected; semantic reuse does not imply containment.
5. **Game autonomous.** Ordivon Game owns ludic semantics and ordinary game presentation. Media is activated only for reusable media assets/productions or explicitly selected media-specific mediation.
6. **Foundations are not modules.** MF0–MF9 constrain interpretation and falsification. They do not map one-to-one onto implementation packages. MF10 remains UNKNOWN / NOT ADMITTED.
7. **Derived reality stays derived.** Publication, interface, authorship, preservation, mediated presence, datafication/legibility and related structures are first-class typed derived realities without hidden primitive promotion.
8. **Consumer-pressure extraction.** Shared Media implementation is extracted only after materially different real consumers reproduce common pressure that owner-local solutions cannot cleanly contain.

## Project inversion — materialized

The physical repository is now `/root/projects/ordivon-media`, and the canonical Media research navigation root remains `research/media/`. The owner-identity inversion is materialized:

```text
old: Studio project containing Media research
new: Media project containing Studio capability
```

The migration is not a global rename of Studio symbols. Existing `ordivon-studio` CLI/package/tool identities remain valid where they name Studio production capability.

See [`docs/media-m0-identity-migration.md`](docs/media-m0-identity-migration.md) for the live M0 preflight and [`research/media/engineering-consumption/OMPC-v0.md`](research/media/engineering-consumption/OMPC-v0.md) for the first technology-neutral projection contract.

## Phase 1 status

Ordivon Media construction Phase 1 (M0–M4) is **closed**. The project is now in a stable-owner / consumer-pressure-driven posture: MF0–MF9 remain historical research constraints, OMPC-v0 is an optional shared reference for tasks that activate Media semantics, Studio remains active as the production capability plane, and no shared Media engine/runtime/SDK is admitted without demonstrated implementation duplication or a concrete consumer falsifier.

See [`docs/media-phase1-construction-audit.md`](docs/media-phase1-construction-audit.md) for the closure, freeze and reopen criteria.
