# 1. Problem statement

MF4-A→H established composition across parts, relations, hierarchy, time, space, multimodality, scene and narrative/discourse organization.

Those rounds still admit a dangerous static bias. Many media/computational/social/game/UI wholes are not defined only by standing structure. They exist through reciprocal state change:

- user ↔ interface;
- controller ↔ plant;
- speaker ↔ addressee;
- player ↔ game state;
- agent ↔ environment;
- agent ↔ agent;
- process ↔ protocol peer;
- organism ↔ niche;
- coordinated limbs/people;
- indirect environment-mediated collectives.

MF4-I asks:

> **When does causal change become interaction, when does interaction become feedback/control, and when do several actions become coordination/joint action rather than mere co-occurrence?**

Dangerous collapses:

`Event = Action`;

`Causal Source = Agent = Controller = Participant`;

`Causal Influence = Interaction`;

`Bidirectionality = Feedback`;

`Feedback = Control`;

`Closed Loop = Stable Loop`;

`Observability = Sensing = Knowledge`;

`Controllability = Authority = Competence`;

`Synchronization = Coordination`;

`Co-action = Joint Action`;

`Shared Goal = Cooperation`;

`Communication = Coordination`;

`Turn Sequence = Conversation`;

`Protocol Conformance = Cooperation`;

`Direct Signaling = Necessary Interaction`;

`Choice = Agency`;

`Branch Count = Interactive Meaning`.

MF4-I rejects all of these as universal identities.

---

# 2. Event is broader than action

An event is a change/process unit under MF4-E/H.

An action is an event occupying an intervention/output role relative to a participant/controller/agent policy or functional organization.

### Result

**CI-01 — Action is a typed event role; not every event is an action.**

---

# 3. Action does not require conscious intention universally

Engineered controllers, organisms and simple agents can select outputs under policies without reflective awareness.

### Result

**CI-02 — Conscious intention is not constitutive of the broad functional action role used in MF4-I.**

---

# 4. But action ≠ mere causal emission

A rock falling and breaking glass is a causal source, but calling the fall an `action` requires additional participant/selection/control attribution under scope.

### Result

**CI-03 — Causal production is insufficient for action attribution.**

---

# 5. Causal source ≠ participant

A disturbance can affect an interaction without occupying a stable interaction role/interface.

### Result

**CI-04 — Causal source and interaction participant are distinct.**

---

# 6. Participant is role-relative

A participant is a unit/system occupying an addressable role in an interaction organization, with some state/interface/history relevant to coupled transitions.

### Result

**CI-05 — Participant status is interaction/scope-relative rather than equivalent to physical objecthood.**

---

# 7. Agent ≠ participant

A sensor, database or passive environment component can participate in a loop without action-selection autonomy.

### Result

**CI-06 — Agency is stronger than participation.**

---

# 8. Provisional functional agency profile

MF4-I does not freeze a metaphysics of agency. A useful functional profile can include:

- maintained system boundary/state;
- alternative action availability;
- action selection policy;
- sensitivity to observation/history;
- outcome/goal/preference constraints;
- persistence across episodes;
- capacity to alter future evidence/options.

### Result

**CI-07 — Agency is provisionally profiled by action-selection organization, not reduced to animation, consciousness or causal force.**

---

# 9. Controller ≠ agent

A controller is a role whose output is recruited to steer selected system variables/outcomes. It can be a fixed feedback circuit without broader agency.

### Result

**CI-08 — Control role is narrower/different from general agency.**

---

# 10. Agent ≠ controller

An agent can participate/explore/communicate without controlling the whole system.

### Result

**CI-09 — Agency does not imply whole-system control authority.**

---

# 11. Interaction is stronger than causal influence

A emits radiation that warms unrelated B: causal influence exists.

Interaction requires a scoped coupled organization in which one participant/environment transition is contingent/recruited relative to another and belongs to the same dynamic whole.

### Result

**CI-10 — One-way causal influence is insufficient for interaction.**

---

# 12. Provisional interaction definition

> **An interaction is a scope-relative dynamic composition in which states, actions or outputs of participants and/or a shared environment are contingently coupled so that one component's current or prior state/action changes the admissible, probable, selected or evaluated subsequent transitions of another component or the shared whole.**

### Result

**CI-11 — Interaction requires organized contingency/coupling, not mere temporal adjacency or causal contact.**

---

# 13. Interaction does not require symmetric influence

A command-response episode can be interactive even if authority/influence is strongly asymmetric.

### Result

**CI-12 — Interaction can be asymmetric.**

---

# 14. Interaction does not require perpetual reciprocity

A short request-response exchange can terminate after one response.

### Result

**CI-13 — Recurrent bidirectionality is not necessary for every interaction episode.**

---

# 15. But a pure broadcast may remain noninteractive

A one-way prerecorded signal that cannot alter its behavior/state in response to a receiver can mediate influence without reciprocal contingency.

### Result

**CI-14 — Addressing an audience does not automatically establish interactive coupling.**

---

# 16. Responsiveness is a central interaction axis

B is responsive to A when B's transition/output depends counterfactually on A's state/action/history under a declared relation.

### Result

**CI-15 — Responsiveness is typed counterfactual dependence, not merely temporal following.**

---

# 17. Response ≠ feedback

B can respond to A without B's response subsequently being recruited to modify A or a controller's next behavior.

### Result

**CI-16 — Response is weaker than feedback.**

---

# 18. Bidirectionality ≠ feedback

A affects B and B independently affects A, yet neither effect need be an output consequence measured/recruited to regulate a prior process.

### Result

**CI-17 — Mutual causal influence alone is insufficient for feedback.**

---

# 19. Provisional feedback definition

> **Feedback exists when consequences/output/state resulting from a process are sensed, transmitted or otherwise recruited back into a later input/control/selection relation that can alter subsequent evolution of that process or coupled whole.**

### Result

**CI-18 — Feedback is a looped information/causal recruitment relation, not generic two-way causation.**

---

# 20. Rosenblueth–Wiener–Bigelow provide an early behavioral control anchor

Their 1943 framework explicitly analyzes input/output behavior and treats negative feedback as central to a restricted account of purposive/teleological behavior.

### Result

**CI-19 — Feedback provides a historically foundational mechanism for outcome-directed regulation, but MF4-I does not equate all purpose/agency with negative feedback.**

---

# 21. Negative feedback ≠ good feedback

Negative feedback opposes/reduces a deviation under a particular loop/sign convention.

### Result

**CI-20 — `Negative` and `positive` feedback are dynamical relation types, not normative labels.**

---

# 22. Positive feedback ≠ always failure

Amplification can be useful in switching, commitment, signaling or threshold processes.

### Result

**CI-21 — Positive feedback can be functional or destabilizing depending on system/goals/saturation.**

---

# 23. Negative feedback ≠ guaranteed stability

Delay, excessive gain, nonlinearities or unmodeled dynamics can yield oscillation/divergence.

### Result

**CI-22 — Sign of feedback is insufficient for closed-loop stability.**

---

# 24. Feedback ≠ control

A loop can feed consequences back without successfully steering a target variable.

### Result

**CI-23 — Feedback is a mechanism/relation; control is a steering capability/policy/evaluation relation.**

---

# 25. Control ≠ feedback

Open-loop control can issue a precomputed control sequence without measuring consequences during execution.

### Result

**CI-24 — Feedback is not necessary for every control episode.**

---

# 26. Open loop ≠ no model

A feedforward/open-loop controller may use a strong model/prediction even without current output feedback.

### Result

**CI-25 — Open-loop organization can be model-rich despite lacking active feedback.**

---

# 27. Closed loop ≠ adaptive learning

A fixed controller can use feedback without changing its policy parameters.

### Result

**CI-26 — Feedback control and learning/adaptation are distinct.**

---

# 28. Adaptation ≠ feedback alone

A system can update policy/model from accumulated outcomes; feedback supplies evidence but adaptation requires a change rule.

### Result

**CI-27 — Adaptation is policy/model change across interaction history, not simply consequence sensing.**

---

# 29. Control target must be typed

Control can target:

- state;
- trajectory;
- output;
- error;
- risk;
- resource use;
- probability distribution;
- information acquisition.

### Result

**CI-28 — `Control` is under-specified without controlled variable/outcome and allowed interventions.**

---

# 30. Controllability ≠ current controller success

A system can in principle be steerable through available inputs while a poor controller fails to steer it.

### Result

**CI-29 — System controllability and actual policy/controller competence are distinct.**

---

# 31. Kalman provides a structural control-system anchor

### Result

**CI-30 — Controllability/observability are system/interface properties distinct from current action quality.**

---

# 32. Controllability ≠ authority

**CI-31 — Causal steering capability and normative/institutional control authority are distinct.**

# 33. Authority ≠ competence

### Result

**CI-32 — Control authority and control competence are separate.**

# 34. Observability ≠ observation

**CI-33 — Structural observability and actual sensing episode are distinct.**

# 35. Observation ≠ knowledge

# 36. Knowledge ≠ control

# 37. Control can exist under partial observation

# 38. Feedback provenance matters

**CI-38 — Feedback usefulness depends on measurement-target validity, not feedback availability alone.**

# 40. Latency is first-class in feedback loops

**CI-39 — Feedback timing is composition-defining for many interaction/control loops.**

# 41. Delay ≠ noise

# 42. Sampling/update rate ≠ latency

# 43. Interaction loop can be stable without equilibrium

# 156. Interaction failure taxonomy

## Nonresponsive coupling

Expected contingent response absent.

## Spurious response

Unrelated event treated as response.

## Feedback break

Outcome fails to re-enter required control/selection loop.

## Stale feedback

Correct but outdated state drives action.

## Feedback sign/gain error

Correction amplifies/diverges from target relation.

## Observability failure

Relevant state distinctions cannot be recovered from available evidence.

## Controllability failure

Available interventions cannot reach/steer relevant states under scope.

## Authority mismatch

Actor has/uses capability without permission or permission without capability.

## Action-role misbinding

Action attributed to wrong participant/agent/controller.

## Coordination phase/timing error

Relative timing/phase/sequence violates whole relation.

## Role collision

Participants choose incompatible actions/roles.

## Under-coordination

Necessary mutual adjustment absent.

## Over-coordination

Unnecessary synchronization/communication creates blocking/cost.

## Protocol-state mismatch

Peers disagree about current interaction state/version.

## Turn-allocation failure

Floor/resource rights collide, starve or deadlock.

## Reference/grounding failure

Participants transmit valid symbols but bind different referents/intent.

## Repair failure

Mismatch is detected but not recoverable/reconciled.

## Stigmergic contamination

Persistent environmental traces are stale/spurious/ambiguous and induce wrong actions.

## Duplicate/retry identity failure

One logical action executes multiple times or distinct actions collapse into one.

## Branch/agency illusion

Nominal choices fail to alter relevant state/outcome despite claimed agency.

## Feedback-proxy misalignment

Measured/evaluated proxy diverges from intended objective.

## Local/global coordination conflict

Subcomponents coordinate successfully while whole objective degrades.

## Unstable loop

Coupling oscillates/diverges outside intended dynamical profile.

## Recovery discontinuity

Interaction cannot preserve/reconstruct required identity/state after interruption.

### Result

**CI-155 — Interaction failure is a typed dynamical/relational family, not one response-time/success scalar.**

# 167. Deepest MF4-I conclusion

The strongest surviving candidate is:

> **An interactive composition exists when states/actions/outputs of participants and/or a shared environment are organized through contingent transition relations such that one component's current or prior state changes the admissible, probable, selected or evaluated subsequent transitions of another component or the shared whole under a declared scope.**

Within that umbrella:

> **Feedback is the recruited return of consequence/output into later input/control/selection; control is steering relative to a target through available interventions; coordination is whole-level relational organization among multiple action streams; cooperation/competition are goal/payoff relations; communication/protocol/turn-taking are particular interaction mechanisms.**

Compactly:

`Interaction = Participants/Environment + Contingent Dynamic Coupling + State/History + Whole/Scope`.

And:

`Feedback ⊂ some Interactions`,

`Control ⊄ Feedback exclusively`,

`Coordination ⊂ organized Interaction`,

without forcing all interaction into one loop architecture.
